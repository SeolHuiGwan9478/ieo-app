# 04. 인수증 (Proof of Delivery)

## 목적

종이 인수증을 **수하인 폰에서 서명하는 전자인수증**으로 바꿔, 하차 직후 주선사에게 바로 전달되게 한다. 기획서 기능 ④를 담당한다.

배경: 인수증이 차주 → 운송사 → 화주로 돌아가야 운임이 지급되는데, 분실·훼손과 우체국 등기 부담이 있다. 1개월 넘게 운임을 받지 못한 거래가 30~40%였다(한국교통연구원 2013).

## 사용자 시나리오

1. 하차 30분 전, 수하인이 받은 ETA 알림에 "인수 확인 링크"가 함께 들어 있다.
2. 하차를 마치면 차주가 정차 화면에서 "인수증 받기"를 누른다. 차량 화면에 QR 코드가 뜬다.
3. 수하인이 QR을 찍거나 알림 링크를 열어, 품목과 수량을 확인하고 손가락으로 서명한다.
4. 서명 즉시 전자인수증(시각, 위치, 서명, 사진)이 만들어져 주선사에게 간다. 차량 화면에는 "인수 완료"가 초록색으로 뜨고 운행이 완료된다.

## 기능 요구사항

| ID | 요구사항 | 우선순위 |
|---|---|---|
| POD-001 | 운행마다 인수 확인 링크를 만든다. 링크는 추측할 수 없는 토큰을 쓰고, 하차 완료 후 7일 뒤 만료된다 | P2 |
| POD-002 | 하차 30분 전 ETA 알림에 인수 확인 링크를 넣는다 ([01_운행.md](01_운행.md) TRIP-021) | P2 |
| POD-003 | 차량 화면에서 "인수증 받기"를 누르면 같은 링크의 QR 코드를 보여 준다. 정차 중에만 누를 수 있다 | P2 |
| POD-004 | 수하인 웹 페이지(설치 불필요)에서 운행 정보(상하차지, 품목, 수량)를 보여 주고 서명을 받는다 | P2 |
| POD-005 | 수하인은 이상 사항(파손, 수량 부족)을 메모와 사진으로 남길 수 있다 | P2 |
| POD-006 | 서명하면 전자인수증을 만든다: 운행 정보, 서명 이미지, 서명 시각, 서명 위치(브라우저 위치, 동의 시), 차량 위치, 이상 사항 | P2 |
| POD-007 | 전자인수증 PDF를 주선사에게 바로 보내고, 차주도 장부에서 볼 수 있다 | P2 |
| POD-008 | 서명이 끝나면 운행을 `COMPLETED`로 바꾸고, 장부의 결제 방식이 "인수증"이면 지급 예정일 계산을 시작한다 | P2 |
| POD-009 | 수하인이 서명하지 못하는 경우를 위해, 차주가 종이 인수증 사진을 찍어 올리는 대체 경로를 둔다 | P2 |
| POD-010 | 서명 후 문서가 바뀌지 않았음을 확인할 수 있게 문서 해시를 저장한다 | P3 |

## 상태

```
 대기 (링크 발급) ──(수하인 서명)──▶ 서명 완료 ──▶ 주선사 전달됨
        │
        └──(차주가 종이 인수증 사진 업로드)──▶ 사진 인수증 ──▶ 주선사 전달됨
```

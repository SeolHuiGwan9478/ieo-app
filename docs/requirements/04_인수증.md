# 04. 인수증 (Proof of Delivery)

## 목적

결제 방식이 **인수증**인 운행에서, 하차지에서 받은 **종이 인수증을 휴대폰으로 찍어 주선사에게 바로 보낸다.** 우편·등기로 원본을 보내는 동안 운임 지급이 늦어지는 일을 줄인다. 기획서 기능 ④를 담당한다.

배경: 인수증이 차주 → 운송사 → 화주로 돌아가야 운임이 지급되는데, 분실·훼손과 우체국 등기 부담이 있다. 1개월 넘게 운임을 받지 못한 거래가 30~40%였다(한국교통연구원 2013).

### 정한 것 (2026-11-12)

- **수하인 서명(전자인수증)은 하지 않는다.** 하차지 담당자는 자기 회사 양식(거래명세서·송장)에 도장을 찍는 게 익숙하고, 남의 앱 QR에 서명해 줄지 의문이다. 아직은 종이로 관리하는 곳이 많다. 차량 화면 QR, 수하인 서명 페이지(`/r/{token}`), 서명 API를 없앴다
- **인수증 결제 운행만** 인수증을 받는다. 선불·착불 운행에는 인수증 화면이 나오지 않는다. 오더마다 "인수증 필요" 칸을 따로 두지는 않았다 (선불·착불인데 인수증을 받는 경우가 흔하면 그때 더한다)
- **찍고 보내는 건 휴대폰, 차량 앱은 보기만.** 차에는 카메라가 없다. 차량 앱은 운행을 마칠 때 알리고, 장부에서 보냈는지와 사진을 보여 준다

## 사용자 시나리오

1. 하차를 마치고 떠남을 확인하면 차량 앱이 "운행을 마쳤어요. 장부에 45만 원을 기록했어요. 인수증 사진은 휴대폰으로 보내 주세요."라고 말한다 (인수증 결제 운행만).
2. 기사님이 휴대폰 내 배차 → 증빙 → 인수증에서 [종이 인수증 찍기]로 1~5장을 찍는다. 잘못 찍은 사진은 눌러서 지운다.
3. [주선사에게 보내기]를 누르면 콘솔 운행 상세에 사진과 보낸 시각이 뜬다. 문자는 보내지 않는다 (2026-11-13).
4. 장부의 지급 예정일이 보낸 날 + 정산 주기로 다시 잡힌다. 차량 앱 장부에는 "인수증 보냄"이 붙고, 줄을 누르면 사진을 볼 수 있다.

| POD-010 | 서명 후 문서가 바뀌지 않았음을 확인할 수 있게 문서 해시를 저장한다 | P3 |
| POD-011 | [주선사에게 보내기]: 사진이 한 장 이상 있어야 보낸다. 보내면 보낸 시각이 남고 사진을 바꿀 수 없다. 주선사는 콘솔 운행 상세에서 본다 (문자 알림은 뺌, 2026-11-13) | P2 |
| POD-012 | 차량 앱: 인수증 결제 운행을 마치면 "인수증 사진은 휴대폰으로 보내 주세요"를 말과 글로 알린다. 장부 줄에 "인수증 보냄"/"인수증 안 보냄", 상세에 보낸 시각과 사진 | P2 |

## 상태

저장하지 않고 사진과 보낸 시각으로 계산한다.

```
 NONE (사진 없음) ──(사진 올림)──▶ PENDING (안 보냄) ──(주선사에게 보내기)──▶ SENT
                                     ▲    │
                                     └────┘ 사진 더 찍기·지우기 (5장까지)
```

## API

| 누가 | 주소 | 하는 일 |
|---|---|---|
| 차주 | `GET /api/trips/{id}/delivery-proof` | required(인수증 결제인지), status(NONE·PENDING·SENT), sentAt, photos, maxPhotos, canUpload |
| 차주 | `POST /api/trips/{id}/delivery-proof/photos` (multipart `file`) | 사진 한 장. 인수증 결제 아님 409 `DELIVERY_409_NOT_RECEIPT`, 하차지 전 409 `DELIVERY_409_TOO_EARLY`, 취소 409, 보낸 뒤 409 `DELIVERY_409_SENT`, 6장째 400 |
| 차주 | `DELETE /api/trips/{id}/delivery-proof/photos/{photoId}` | 보내기 전 사진 지우기 |
| 차주 | `GET /api/trips/{id}/delivery-proof/photos/{photoId}` | 사진 파일 |
| 차주 | `POST /api/trips/{id}/delivery-proof/send` | 보내기. 사진 없음 409 `DELIVERY_409_NO_PHOTO` |
| 주선사 | `GET /api/brokers/me/trips/{id}` | `receipt: { sentAt, photos[{id, path}] }`. 보내기 전이면 없음 |
| 주선사 | `GET /api/brokers/me/trips/{id}/receipt-photos/{photoId}` | 보낸 인수증의 사진 파일 |
| 차주 | `GET /api/ledger` | 줄마다 `receiptSentAt` |

DB를 바꾸는 스크립트: 서버 `scripts/delivery-proofs-paper-only.sql` (예전에 올린 종이 사진은 보낸 것으로 본다).

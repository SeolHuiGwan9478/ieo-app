# 10. 음성·안전 UX (Voice & Safety)

## 목적

운전 중 차주가 **화면을 보거나 만지지 않고** Ieo를 쓸 수 있게 한다. 모든 도메인의 차량 안 안내(음성)와 명령(음성·버튼), 주행 상태에 따른 화면 제약을 한곳에서 정한다. 심사 기준 "차량특화성"의 핵심이다.

## 원칙

1. **주행 중에는 음성이 기본이다.** 화면은 보조로만 쓰고, 터치가 필요한 기능은 정차 중에만 연다.
2. **한 번에 하나만 말한다.** 안내가 겹치면 우선순위가 높은 것부터 순서대로 말한다.
3. **되돌릴 수 없는 행동은 한 번 더 묻는다.** 배차 수락, 증빙 전송.
4. **길 안내 음성을 방해하지 않는다.** 내비가 안내 중이면 끝날 때까지 기다린다.

## 기능 요구사항

### 주행 상태와 화면

| ID | 요구사항 | 우선순위 |
|---|---|---|
| UX-001 | 주행·정차를 `CarUxRestrictionsManager` 제한 상태와 CarPropertyManager(속도, 기어)로 판단한다 | P1 |
| UX-002 | 주행 중 화면: 지금 상태 한 가지(예: 운송 중, ETA 15:40)와 큰 버튼 최대 2개만 보여 준다 | P1 |
| UX-003 | 정차 중 화면: 운행 상세, 추천 카드 목록, 장부, 상하차지 정보, 설정을 연다 | P1 |
| UX-004 | 주행 중 터치가 필요한 화면에 있었다면 출발과 동시에 주행 중 화면으로 바뀐다 | P1 |
| UX-005 | 글자는 최소 24sp, 버튼은 최소 76dp. 상태색은 글자와 함께 쓴다 | P1 |
| UX-006 | 라이트·다크 모드를 시스템 설정에 따른다. 팔레트는 [design/README.md](../../design/README.md) | P1 |

### 내비와 나란히 쓰기 (화면 분할)

기사님은 운행 중 내비를 계속 켜 둔다. 그래서 **내비 옆 반 화면에 Ieo를 띄우는 모습**을 기본 사용 형태로 본다.
Pleos 화면은 고정 영역(Driving view)과 앱 영역으로 나뉘고, 앱 영역에는 창을 최대 2개 띄울 수 있다. 앱 영역 오른쪽 가장자리의 손잡이(⋮)를 끌면 내비가 옆 창에 붙는다. 에뮬레이터(2.1.0, 1920×1080, 120dpi)에서 반 화면 창은 약 840dp × 1200dp(세로가 긴 창)였다.

| ID | 요구사항 | 우선순위 |
|---|---|---|
| UX-040 | 화면 방향(`screenOrientation`)을 지정하지 않는다. `landscape`로 지정하면 세로로 긴 반 화면 창에 들어가지 못하고 "창 크기를 넓게 조정하세요"만 보인다 (에뮬레이터 확인) | P1 |
| UX-041 | 창 폭에 따라 두 레이아웃을 둔다. 반 화면(좁은 창)이 기본이고, 앱 영역 전체(넓은 창)에서는 정보를 두 칸으로 펼친다 | P1 |
| UX-042 | 좁은 창: 왼쪽 메뉴는 아이콘과 짧은 글자만 남기고, 홈은 한 칸으로 쌓는다. 가장 중요한 정보(오더 목록, 대기 타이머, 도착 시각)가 스크롤 없이 보여야 한다 | P1 |
| UX-043 | 앱 안에 지도를 그리지 않는다. 지도가 필요하면 NaviHelper `requestNavigationScreen`으로 내비 화면(경로 개요 등)을 연다 | P2 |
| UX-044 | Ieo는 턴바이턴 길 안내를 하지 않는다. 길 안내는 내비에 맡긴다 ([01_운행.md](01_운행.md) TRIP-015) | P1 |

### 음성 안내 (TTS)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| UX-010 | 안내 우선순위: 경고(휴게, 높이 제한) > 운행 상태(도착, 대기 시작) > 배차 추천 > 정보(상하차지 카드, 리포트) | P1 |
| UX-011 | 안내 문장은 15초 안에 끝나게 짧게 쓴다. 숫자는 듣기 쉽게 읽는다 (예: "28만 원") | P1 |
| UX-012 | 내비 길 안내 음성이 나오는 중에는 기다렸다가 말한다 (오디오 포커스 정책 준수) | P2 |
| UX-013 | 음악·라디오 재생 중에는 소리를 잠시 줄이고(ducking) 말한 뒤 되돌린다 | P2 |
| UX-014 | 안내를 다시 듣고 싶으면 "다시"라고 말한다 | P2 |

### 음성 명령 (STT)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| UX-020 | 질문형 안내 뒤 8초 동안 답을 듣는다: "응/수락/맞아", "아니/다음", "다시" | P2 |
| UX-021 | 핸들 음성 버튼이나 화면 마이크 버튼으로 명령을 시작한다: "상차 시작", "주유 15만 원", "대기 증빙 보내", "오늘 얼마 벌었어" | P2 |
| UX-022 | 인식 결과가 애매하면 실행하지 않고 다시 묻는다. 두 번 실패하면 "정차 후 화면에서 해 주세요"라고 안내한다 | P2 |
| UX-023 | 한국어 숫자·금액 표현("십오만 원", "15만", "만 오천")을 정규화한다 | P2 |
| UX-024 | 시스템 음성비서 연동(Gleo Interface, 함수 최대 3개)에는 가장 자주 쓰는 명령 3개를 등록한다: 대기 시작·끝, 경비 기록, 다음 배차 듣기 | P3 |

### 1차 데모용 대체 경로

| ID | 요구사항 | 우선순위 |
|---|---|---|
| UX-030 | TTS·STT SDK 승인 전에는 Android 기본 TextToSpeech와 SpeechRecognizer로 같은 흐름을 만든다. 음성 처리는 인터페이스 하나로 감싸 나중에 Pleos SDK로 바꾼다 | P1 |

## 음성 대화 예

```
Ieo   : 칠곡 오후 4시 상차, 부산행 5톤, 실수익 28만 원 건이 있습니다. 자세히 들을까요?
차주  : 응
Ieo   : 대구 하차지에서 30분 거리입니다. 주선사는 ○○물류, 결제는 인수증입니다. 수락할까요?
차주  : 수락
Ieo   : 칠곡 부산행을 수락할까요? 맞으면 "응"이라고 해 주세요.
차주  : 응
Ieo   : 수락 요청을 보냈습니다. 확정되면 알려 드릴게요.
```

## 미결 사항

- [ ] TTS·STT SDK의 연속 인식·웨이크워드 지원 여부 (문서에서 확인 안 됨)
- [ ] Pleos TextToSpeech SDK 앱 인증 정보 받기: SDK(ai.pleos.playground:TextToSpeech 3.3.1)는 권한 `pleos.car.permission.TTS_SERVICE`로 붙지만, 서버 합성은 "Client credentials missing"으로 거절되고 에뮬레이터에는 기기 안 엔진이 없다 (2026-11-05 확인). Android 기본 TextToSpeech는 Pleos 음성 서비스에 붙지 못한다
- [ ] 에뮬레이터에서 마이크 입력 테스트 방법
- [ ] 앱이 직접 2창 모드를 요청할 수 있는지 (지금은 사용자가 손잡이를 끌어 나눈다)
- [ ] Gleo Interface 검토 절차와 기간 확인
- [ ] `[인터뷰]` 차 안 소음(엔진, 라디오)에서 음성 인식이 쓸 만한지, 기사님이 말로 하는 걸 편하게 느끼는지

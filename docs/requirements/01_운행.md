# 01. 운행 (Trip)

## 목적

배차 1건을 배차 확정(또는 직접 등록)부터 하차 완료까지 추적한다. **Ieo의 중심 도메인**이며 대기, 인수증, 장부, 배차 추천이 모두 운행 하나를 기준으로 붙는다. 기획서 기능 ① ETA 알림과 ⑥ 휴게 관리를 담당한다.

## 사용자 시나리오

1. 차주가 Ieo 오더 마켓에서 평택→대구 오더에 배차를 요청하고, 주선사가 확정한다 ([11_배차.md](11_배차.md)). 운행이 예약 상태로 자동 등록된다.
   - 다른 앱이나 전화로 받은 일이라면, 운전석에서 "평택 삼성 상차, 대구 성서 하차, 운임 45만 원, 인수증"이라고 말해 등록한다. 정차 중에는 화면으로 직접 입력해도 된다.
2. 출발하면 앱이 상차지로 길 안내를 요청한다.
3. 상차지에 도착해 대기와 상차를 마친다 ([02_대기.md](02_대기.md)). 상차를 마치고 출발하면 하차지로 길 안내가 바뀐다.
4. 주행 중 진행률이 1/2, 2/3 지점을 지날 때마다 주선사·수하인에게 도착 예정 시각이 자동으로 간다. 차주는 아무것도 누르지 않는다.
5. 연속 주행이 2시간에 가까워지면 "15분 뒤 휴게소에서 쉬어야 합니다"라는 음성 안내가 나온다.
6. 하차지에 도착해 하차를 마치면 운행이 완료되고, 장부에 한 줄이 생긴다.

## 기능 요구사항

### 운행 등록

운행이 생기는 경로는 두 가지다. **Ieo 오더 마켓의 배차 확정(기본)**과 **다른 앱·전화로 받은 일의 직접 등록(보조)**. 1차 제출(P1)은 오더 마켓 전이라 직접 등록으로 시연한다.

| ID | 요구사항 | 우선순위 |
|---|---|---|
| TRIP-001 | 정차 중 화면에서 상차지, 하차지, 운임, 결제 방식, 주선사, 상하차 예정 시각을 입력해 운행을 등록한다 | P1 |
| TRIP-002 | 상하차지는 주소 검색으로 입력하고 좌표로 저장한다 | P1 |
| TRIP-003 | 음성으로 운행을 등록한다. 인식 결과를 음성으로 다시 읽어 주고 "맞아"라고 답하면 확정한다 | P2 |
| TRIP-004 | Ieo 오더 마켓에서 배차가 확정되면(`DispatchConfirmed`) 오더 내용으로 운행을 자동 생성한다 ([11_배차.md](11_배차.md)) | P2 |
| TRIP-005 | 다음 배차 추천으로 배차가 확정되어도 같은 방식으로 운행이 생성된다 ([03_배차추천.md](03_배차추천.md)) | P2 |
| TRIP-006 | 운행 하나에 상하차지를 여러 개(경유 하차) 둘 수 있다 | P3 |
| TRIP-007 | 운행마다 출처(Ieo 배차 / 직접 등록 / 음성 등록)를 기록한다. Ieo 배차 운행만 노선 평균 운임 통계에 쓴다 | P2 |

### 진행 추적

| ID | 요구사항 | 우선순위 |
|---|---|---|
| TRIP-010 | 운행 상태를 아래 상태도대로 관리한다. 상태 전환은 위치·주행 신호로 자동 판단하고, 차주가 음성이나 버튼으로 바로잡을 수 있다 | P1 |
| TRIP-011 | 운송 중 진행률 = (전체 경로 거리 − 남은 거리) / 전체 경로 거리. 남은 거리는 NaviHelper에서 읽는다 | P1 |
| TRIP-012 | 진행률이 50%, 67%를 처음 넘을 때 `TripProgressed` 이벤트를 낸다 | P1 |
| TRIP-013 | 위치는 운행 중 5분 간격으로 서버에 보낸다. 끊기면 차량에 쌓아 두었다가 한꺼번에 보낸다 | P1 |
| TRIP-014 | 상차를 마치고 출발하면 하차지로 길 안내를 자동 요청한다 (NaviHelper `requestRoute`) | P2 |
| TRIP-015 | 길 안내와 턴바이턴 음성은 차량 내비가 맡는다. Ieo는 목적지·경유지(최대 2개)를 넘기고 결과만 읽는다 (Pleos 단일 경로 원칙) | P1 |
| TRIP-017 | 홈의 "내 배차"에서 배차를 누르면 "안내를 시작할까요?" 확인 창을 띄운다. [안내 시작]을 누르면 상차지로 길 안내를 요청하고, 홈은 내비가 알려 주는 도착 예정 시각·남은 거리·남은 시간·진행률을 보여 준다. 내비에서 안내를 끄면(`onRouteCancelled`) 홈 목록으로 돌아온다 | P1 |
| TRIP-016 | NaviHelper에는 화물차 전용 경로 옵션(높이·중량)이 없다. 경로 옵션은 기본값(추천)을 쓰고, 화물차 경로 지원은 기획서에 플랫폼 제안으로 남긴다 | P1 |
| TRIP-034 | (2026-11-11 결정) 차량 앱의 길 안내는 차량 내비로 고정한다. 도착 예정 알림(ETA)·남은 거리·진행률·다음 배차 추천 시점·바로 도착이 모두 내비 값에 기대므로, 휴대폰 지도로 안내하면 이 기능이 빠진다. 휴대폰 앱은 자체 길 안내가 없고, 현장 정보의 [길 안내]는 TMAP이 있으면 TMAP에 목적지를 넘기고(`tmap://route`) 없으면 휴대폰 기본 지도 앱을 연다. 운행 전에 미리 길을 볼 때 쓰는 용도다 | P1 |
| TRIP-035 | (2026-11-11) 운행 중 화면은 이에오와 차량 내비를 반씩 나란히 띄우는 것을 기본으로 한다. 도착 확인·추천 수락 창이 내비 옆에 보이게 하기 위함이다. 기사님이 내비를 직접 전체 화면으로 키우면 이에오는 음성으로만 묻고 듣는다. 길 안내를 시작할 때 반반으로 열 수 있는지는 Pleos에서 확인 필요(에뮬레이터에서 손잡이로 반반이 되는 것은 확인) | P1 |

### ETA 알림 (기능 ①)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| TRIP-020 | 하차 ETA = NaviHelper의 남은 시간 + 남은 휴게 시간. 내비 정보가 없으면 남은 직선거리 / 최근 평균 속도로 추정한다 | P1 |
| TRIP-021 | 출발, 진행률 50%, 도착 30분 전, 도착 시점에 주선사에게 ETA를 알린다 | P1 |
| TRIP-022 | 직전 알림보다 ETA가 15분 이상 바뀌면 다시 알린다. 단, 같은 운행에서 재알림은 30분에 한 번까지 | P1 |
| TRIP-023 | 알림 링크를 열면 차량 현재 위치(지도)와 ETA를 볼 수 있다. 링크는 하차 완료 후 24시간 뒤 만료된다 | P2 |
| TRIP-024 | 차주는 운행별로 ETA 알림을 끌 수 있다 | P1 |

### 연속 운전·휴게 관리 (기능 ⑥)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| TRIP-030 | 연속 주행 시간을 잰다. 정차가 15분 이상 이어지면 휴게로 보고 0으로 되돌린다 | P2 |
| TRIP-031 | 연속 주행이 1시간 45분이 되면 휴게 필요를 음성으로 알리고, 2시간이 되면 경고(빨강)로 다시 알린다 | P2 |
| TRIP-032 | 휴게 안내 때 경로 위 다음 휴게소·졸음쉼터까지 거리를 함께 알려 준다 | P3 |
| TRIP-033 | 남은 경로에 필요한 휴게 시간을 ETA에 더한다 | P2 |

## 상태

```
          등록
            │
            ▼
 ┌──── 예약됨 (SCHEDULED) ────────────────────────────┐
 │          │ 출발 (상차지 방향 주행 시작)              │
 │          ▼                                         │
 │    상차지 이동 (TO_PICKUP)                          │
 │          │ 상차지 진입 (지오펜스)                    │
 │          ▼                                         │
 │    상차 중 (AT_PICKUP) ── 대기·작업은 [대기] 도메인   │ 취소
 │          │ 상차지 이탈                               │ (CANCELLED)
 │          ▼                                         │
 │    운송 중 (IN_TRANSIT) ── 진행률·ETA·휴게           │
 │          │ 하차지 진입                               │
 │          ▼                                         │
 │    하차 중 (AT_DROPOFF)                             │
 │          │ 하차 완료 (인수 서명 또는 하차지 이탈)      │
 │          ▼                                         │
 └──▶ 완료 (COMPLETED) ◀───────────────────────────────┘
```

- `CANCELLED`는 `COMPLETED` 전 어느 상태에서나 갈 수 있다.
- 지오펜스 반경 기본값은 300m이고, 상하차지마다 조정할 수 있다 ([05_상하차지.md](05_상하차지.md)).

## 데이터

| 엔티티 | 주요 필드 |
|---|---|
| Trip | id, driverId, vehicleId, brokerId?, orderId?, status, fare, paymentType(선불/착불/인수증), expectedPaymentDate?, source(IEO_DISPATCH/MANUAL/VOICE), createdAt, completedAt |
| TripStop | id, tripId, type(PICKUP/DROPOFF), siteId, sequence, plannedAt, arrivedAt, departedAt |
| TripPosition (`trip_positions`) | tripId, lat, lng, recordedAt, remainMeters?, remainSeconds?, routeMeters?. 운행마다 마지막 위치 한 줄만 덮어쓰고, 운행이 끝나면 지운다 (이력·속도·기어는 남기지 않음) |
| EtaNotice | id, tripId, recipientType(주선사/수하인), eta, sentAt, reason(출발/50%/30분전/도착/변경) |
| DrivingSession | tripId, startedAt, endedAt (연속 주행 구간) |

## 외부 의존

| 대상 | 쓰임 |
|---|---|
| NaviHelper SDK | 남은 거리·시간, ETA, 길 안내 요청, 도착 이벤트 |

## 미결 사항

- [ ] 주소 검색 API 선정 (카카오 로컬 API 유력)
- [ ] 화물자동차 운수사업법의 휴게 기준(2시간 운전 후 15분) 원문 확인
- [ ] `[인터뷰]` 수하인에게 ETA 알림을 보내도 되는지, 보통 누가 "어디쯤이에요?" 전화를 하는지
- [ ] NaviHelper가 없는 차량(내비 미탑재)에서의 동작 범위
- [x] 좌표만으로 `requestRoute`가 되는지 → 된다. poiId를 빈 값으로 보내도 내비가 경로 후보를 띄우고 안내를 시작한다 (2026-10-22 에뮬레이터)

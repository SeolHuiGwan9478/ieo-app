# 11. 배차 (Order Market)

## 목적

Ieo 안에서 **주선사가 오더를 올리고 차주가 오더를 찾아 배차를 받는** 오더 마켓(화물 정보망)을 운영한다. 다른 앱이나 전화로 받은 일을 등록하는 경로([01_운행.md](01_운행.md))는 보조 경로로 남겨 둔다.

### 운영 원칙

1. **Ieo는 정보만 제공한다.** 운송 계약은 주선사와 차주가 맺는다. 차주의 배차 요청을 **주선사가 확정**하는 구조로, Ieo가 계약을 중개하거나 대리하지 않는다. (2027.9 시행 화물운송플랫폼법: 운송주선사업 허가 없는 유상 중개·대리 금지)
2. **오더마다 돈을 받지 않는다.** 수입은 월정액 구독뿐이다 ([12_요금제_결제.md](12_요금제_결제.md)). 오더 열람과 배차는 모든 플랜에서 무료다.
3. **클릭 경쟁을 만들지 않는다.** 선착순 클릭은 운전 중 화면 조작과 매크로('지지기')를 부른다. 기본은 "요청 → 주선사 선택" 방식이다.
4. **다단계를 줄인다.** 재위탁 오더를 막고, 실제 운임 정보를 차주에게 보여 준다.

## 사용자 시나리오

1. ○○물류 배차 담당자가 웹 콘솔에 평택→대구 5톤 오더를 올린다. 상하차 시간, 화물, 무게, 상하차 방식, 운임, 결제 방식, 지급 예정일을 빠짐없이 적어야 등록된다.
2. 평택 근처에서 정차 중인 차주의 화면에 조건이 맞는 오더 3건이 뜬다. 각 오더에 "이 노선 최근 평균 운임 47만 원", "○○물류 평균 지급 12일"이 함께 보인다.
3. 차주가 "배차 요청"을 누른다. 주행 중이라면 "평택 대구 건 요청할까요?" → "응"으로 요청한다.
4. 담당자가 요청한 차주 3명 중 한 명을 고르면 확정 알림이 가고, 차주의 운행이 예약 상태로 생긴다.

| DSP-003 | 오더마다 위탁 관계를 고른다: 화주에게 직접 받은 오더 / 다른 운송사·주선사에게 받은 오더. 후자는 재위탁 경고 대상이다 | P2 |

| DSP-006 | 오더를 특정 차주에게만 보낼 수 있다 (단골 차주 지정 배차) | P2 |

| ID | 요구사항 | 우선순위 |
|---|---|---|
| DSP-010 | 정차 중 화면에서 오더를 목록과 지도로 본다. 필터: 상차지 거리, 하차 방향, 톤수·차종, 상차 날짜, 최소 운임, 결제 방식 | P2 |
| DSP-011 | 오더 카드에 운임, **실수익**, 주선사 신뢰 지표, 노선 최근 평균 운임을 함께 보여 준다. 목록은 호출을 아끼려고 기름값만 뺀 어림값("약")이고, 상세는 TMAP 경로로 기름값·통행료를 뺀 값이다 | P2 |
| DSP-012 | 주행 중에는 목록을 보여 주지 않는다. "근처 오더 있어?"라고 물으면 조건에 맞는 상위 1건을 음성으로 읽는다 | P2 |
| DSP-013 | 차주가 저장한 조건에 맞는 새 오더가 올라오면 알린다. 주행 중에는 음성으로 한 줄만, 정차 중에는 카드로 | P2 |
| DSP-014 | 다음 배차 추천은 이 오더 마켓 위에서 동작한다 ([03_배차추천.md](03_배차추천.md)) | P2 |

### 배차 요청과 확정

| ID | 요구사항 | 우선순위 |
|---|---|---|
| DSP-020 | 차주가 오더에 배차를 요청한다. 음성 요청은 한 번 더 확인한다 ([10_음성_안전UX.md](10_음성_안전UX.md) UX-020) | P2 |
| DSP-021 | 주선사는 요청한 차주 목록(차량, 현재 위치, 상차지까지 거리, 이행 기록)을 보고 한 명을 확정한다 | P2 |
| DSP-022 | 확정되면 오더는 마감되고, 차주에게 확정 알림이 가며 운행이 `SCHEDULED`로 만들어진다. 나머지 요청자에게는 마감을 알린다 | P2 |
| DSP-023 | 요청 후 10분 안에 확정되지 않으면 요청이 만료되고 차주에게 알린다 | P2 |
| DSP-024 | 차주 한 명이 동시에 걸어 둘 수 있는 요청은 3건까지다 | P2 |
| DSP-025 | 같은 차주가 짧은 시간에 요청을 반복하면 막는다 (매크로 방지) | P2 |
| DSP-026 | 필수 서류 4종(사업자등록증·자동차등록증·운전면허증·화물운송종사 자격증)이 모두 승인된 차주만 배차를 요청한다. 승인 전에도 오더는 보이지만 상하차지는 시·구까지, 주선사·화물 내용은 가린다 (가입만 하고 오더를 긁어 가지 못하게) | P2 |

### 취소

| ID | 요구사항 | 우선순위 |
|---|---|---|
| DSP-030 | 확정 후 차주나 주선사가 취소할 수 있다. 취소 사유를 고르게 하고 기록한다 | P2 |
| DSP-031 | (2026-11-12 바꿈) 취소는 시점에 따라 다르게 다룬다. ① 확정 ~ 상차 예정 2시간 전: 휴대폰에서 사유를 골라 취소, 기록에 남지 않는다. ② 상차 예정 2시간 이내 ~ 상차 전: 취소는 되지만 "늦은 취소"로 이행 기록에 남고, 취소 전에 경고를 보여 준다. ③ 상차한 뒤(운송 중·하차지): 앱에서 취소할 수 없다. 주선사에게 연락해 주선사가 취소한다. 차량 앱에는 취소 버튼을 두지 않는다(운전 중) | P2 |
| DSP-032 | 주선사는 요청한 차주와 단골 차주의 인증 여부·완료 운행 수·직전 취소 수를 본다. 차주도 내 정보에서 "주선사에게 보이는 내 기록"으로 같은 값을 본다 | P2 |
| DSP-033 | (2026-11-12) 차주가 30일 안에 늦은 취소를 3번 하면, 3번째 취소 때부터 7일 동안 배차를 요청할 수 없다. 요청 때 언제까지 막혔는지 알려 준다 | P2 |
| DSP-034 | (제외, 2026-11-12) 크레딧을 만들지 않기로 해서 뺐다. 이전 내용: 크레딧: 늦은 취소면 차주 크레딧을 돌려주지 않고, 주선사가 늦게 취소하면 차주 크레딧을 돌려준다. 크레딧 차감 규칙(12 요금제)을 정한 뒤 붙인다. 코드에는 TODO로 남긴다 | P3 |

## 상태

```
 등록됨 (OPEN) ──(첫 요청)──▶ 요청 받음 (REQUESTED) ──(주선사 확정)──▶ 배차 완료 (ASSIGNED)
     │                             │                                    │
     │                             └─(요청 모두 만료)─▶ OPEN              └─(취소)─▶ OPEN 또는 CLOSED
     └─(상차 시간 지남 / 주선사 내림)─▶ 마감 (CLOSED)
```

## 구현 메모 (2026-11-10)

- DSP-010 거르기: 서버는 상차 날짜, 최소 운임, 결제 방식, 하차 지역(주소 앞부분)을 받는다. 상차지 거리는 반경(`radiusM`, 도로 거리 어림 기준)으로 거른다. 앱은 거리·운임·결제를 서버에 넘기고 날짜·제외할 화물은 받은 목록에서 거른다
- DSP-011 거리: 목록의 상차지까지 거리는 도로 거리 어림(직선 × 1.3), 상세는 TMAP 실제 경로라 조금 다를 수 있다. 반경 거르기도 같은 도로 거리 어림을 써서, 목록에 고른 반경보다 큰 거리가 보이지 않는다
- DSP-010 제외할 화물 (2026-11-11): 오더 조건의 제외할 화물은 배차 추천의 제외할 화물(REC-004)과 같은 설정이다. 서버에는 추천 설정(`PUT /api/recommendation-preference`의 `excludedCargoCategories`)으로 저장하고, 오더 탭을 열거나 새로 받을 때 다시 읽는다. 두 화면에 "배차 추천에도 / 오더 찾기 조건에도 똑같이 적용돼요"를 적었다
- DSP-025: 1분 안에 요청 5건을 넘기면 429 (`DISPATCH_429_FAST`). 대기 중 3건 제한(DSP-024)과 따로 센다
- DSP-041: 등록은 막지 않고 표시만, 운영자 목록으로 본다
- DSP-044: 노선은 상하차 시·구, 최근 90일, 10건 이상
- 아직 없음: DSP-012(주행 중 음성으로 근처 오더), DSP-013(저장한 조건의 새 오더 알림). 차주 위치를 언제 어떻게 받을지 정한 뒤 만든다

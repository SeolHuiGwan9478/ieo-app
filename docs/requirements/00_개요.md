# Ieo 요구사항: 개요

기획서([../기획서_초안_v0.1.md](../기획서_초안_v0.1.md))의 기능 ①~⑨와 오더 마켓, 요금제를 도메인별로 나눈 요구사항 문서다.

**Ieo = 오더 마켓(화물 정보망) + 운행 비서.** 주선사가 Ieo에 올린 오더를 차주가 잡는 것이 기본 경로이고, 다른 앱이나 전화로 받은 일도 등록해서 운행 비서 기능을 똑같이 쓸 수 있다. 각 도메인 문서는 같은 틀(목적 → 사용자 시나리오 → 기능 요구사항 → 데이터 → 상태 → 외부 의존 → 미결 사항)을 따른다.

### 도메인 관계

```
[주선사] ── 오더 등록 ──▶ [배차(오더 마켓)] ◀── 다음 배차 추천 ── [배차 추천]
   ▲                          │ 배차 확정                            ▲
   │                          ▼                                     │ 진행률 이벤트
   │   다른 앱·전화로 받은 일 ──▶ [운행] ◀── 음성 등록 ── [음성·안전 UX]
   │                          │  │  │
   │                          │  │  └──────────────────────────────┘
   │                          │  └──── 상하차지 진입/이탈 ─▶ [대기] ─▶ 대기 증빙
   │                          └─────── 하차 완료 ─▶ [인수증]
   │                                       │
   │   지급 이력 ◀── [장부] ◀── 운행·대기·인수증 결과가 장부 한 줄로 모임
   │                   │
   └── 신뢰 지표 ◀─────┘
                       [상하차지] ◀── 대기 통계·음성 메모가 쌓임

[계정·차량]  차주·차량 정보를 모든 도메인에 제공
[요금제·결제] 차주·주선사 플랜에 따라 기능 권한을 결정
[알림]       모든 도메인의 발송 요청 처리 (ETA, 대기 증빙, 인수 링크, 배차 확정, 미수금)
```

- **운행(Trip)이 중심 애그리거트**다. 대기, 인수증, 장부 기록은 모두 하나의 운행에 속한다.
- 운행의 출처는 두 가지다. **Ieo 오더 마켓에서 배차 확정**(기본)과 **다른 앱·전화로 받은 일의 직접 등록**(보조).
- 도메인 사이는 **이벤트로 연결**한다. 예: `DispatchConfirmed` → 운행 생성, 상하차지 도착 → 대기 시작.

## 공통 용어

| 용어 | 뜻 |
|---|---|
| 차주 | 화물차를 소유하고 운전하는 기사. Ieo의 1차 사용자 |
| 주선사 | 화주와 차주 사이에서 배차와 정산을 맡는 운송주선업체 |
| 화주 / 수하인 | 짐을 보내는 쪽 / 받는 쪽 |
| 운행 (Trip) | 배차 1건. 상차지에서 하차지까지의 운송 |
| 상차지 / 하차지 | 짐을 싣는 곳 / 내리는 곳. 둘을 묶어 정류지(Stop)라 부름 |
| 대기 | 상하차지에 도착한 뒤 작업이 시작되기 전까지 기다리는 시간 |
| 공차 | 짐 없이 빈 차로 달리는 것 |
| 실수익 | 운임에서 공차·운송 구간의 기름값과 통행료를 뺀 금액. 보험·차량 할부 같은 고정비는 빼지 않는다 |
| 결제 방식 | 선불(상차지 현장 지급), 착불(하차지 현장 지급), 인수증(인수증 제출 후 후정산) |

## 우선순위 표기

공모전 일정에 맞춘 3단계. 각 요구사항 ID 옆에 표기한다.

| 표기 | 시점 | 뜻 |
|---|---|---|
| **P1** | 1차 제출 (~11/14) | 시연 영상에 들어갈 최소 기능 |
| **P2** | 2차 PT (~12/03) | 실제 동작해야 하는 기능 |
| **P3** | 향후 | 기획서에만 제시 |

요구사항 ID는 `도메인약어-번호` 형식이다. 예: `TRIP-001`, `WAIT-003`.

## 단계별 범위 요약

| 단계 | 포함 |
|---|---|
| P1 | 운행 등록(직접 입력), 진행률·ETA 계산, ETA 알림(SMS), 대기 자동 기록·대기비 계산, 주행 중 안전 모드 |
| P2 | Ieo 오더 마켓(주선사 오더 등록, 차주 탐색·배차 요청·확정), 배차 추천(세웠을 때 근처 Top 3), 인수증 사진 보내기, 휴게 관리, 자동 장부·경비 음성 기록, 세금계산서 발행 시연(모의 발행), 상하차지 정보 카드, 주선사 콘솔(위치 확인), 플랜 전환 시연 |
| P3 | 음성 운행 등록, 구독 결제, 세금계산서 실제 발행, 주선사 신뢰 지표·데이터 리포트, 재위탁 자동 탐지, 대기비 청구 대행, 선지급 금융 제휴 |

P3에도 없는, 아직 요구사항 ID가 없는 아이디어는 [../추후_개발_아이디어.md](../추후_개발_아이디어.md)에 모은다.

## 공통 비기능 요구사항

| ID | 요구사항 |
|---|---|
| NFR-001 | 앱은 주행 중 CPU 5% 미만, 메모리 400MB 이하를 쓴다 (Pleos 심사 기준) |
| NFR-002 | 주행 중에는 터치 조작 없이 음성만으로 핵심 흐름(알림 듣기, 수락·거절)을 끝낼 수 있다 |
| NFR-003 | 네트워크가 끊겨도 위치·대기 기록은 차량에 저장했다가 연결되면 서버로 보낸다 |
| NFR-004 | 위치와 주행 기록은 개인정보다. 수집 목적을 가입 때 알리고, 차주가 동의한 범위만 주선사에 공유한다 |
| NFR-005 | 화면 글자는 최소 24sp, 주요 버튼은 최소 76dp로 한다 (고령 사용자, 차량 화면 거리) |
| NFR-006 | 상태는 색만으로 구분하지 않고 글자를 함께 쓴다 ([design/README.md](../../design/README.md) 팔레트 규칙) |
| NFR-007 | 2027.9 시행되는 화물운송플랫폼법을 고려해 오더·배차 건마다 받는 요금을 만들지 않는다. 수입은 월정액 구독뿐이다 ([12_요금제_결제.md](12_요금제_결제.md)) |
| NFR-008 | Ieo는 운송 계약을 중개·대리하지 않는다. 계약은 주선사의 배차 확정으로 주선사와 차주 사이에 맺어진다 ([11_배차.md](11_배차.md)) |

## 시스템 구성 (요약)

- **차량 앱 (Android, Pleos Connect):** 위치·주행 신호 수집, 음성 UI, 화면 표시. 판단 로직은 최소화
- **서버 (Spring Boot):** 운행 상태 관리, ETA·대기비·실수익 계산, 추천, 알림 발송, 주선사 웹 콘솔 API
- **주선사 웹 콘솔:** 오더 등록, 배차 확정, 차량 위치·ETA 확인, 대기 증빙 조회, 정회원 데이터 리포트
- **공개 웹 페이지:** 주선사가 링크로 여는 대기 증빙 페이지 (설치 불필요). 인수증은 휴대폰으로 찍어 보낸 종이 사진을 콘솔에서 본다

# 09. 알림 (Notification)

## 목적

모든 도메인의 외부 발송(주선사, 수하인, 가족 등)을 한곳에서 처리한다. 발송 채널, 템플릿, 중복 방지, 발송 기록을 관리한다. 차량 안에서 차주에게 말하는 음성 안내는 [10_음성_안전UX.md](10_음성_안전UX.md)에서 다룬다.

## 발송 종류

| 종류 | 받는 사람 | 트리거 | 채널 | 우선순위 |
|---|---|---|---|---|
| ETA 알림 | 주선사, 수하인 | 출발, 진행률 50%, 도착 30분 전, 도착, ETA 변경 | 알림톡(실패 시 SMS) | P1 |
| 인수 확인 링크 | 수하인 | 도착 30분 전 ETA 알림에 포함 | 알림톡 | P2 |
| 대기 증빙 | 주선사 | 차주 요청 | 알림톡 | P1 |
| 전자인수증 전달 | 주선사 | 수하인 서명 | 알림톡 + 콘솔 | P2 |
| 배차 요청 | 주선사 | 차주가 오더에 배차 요청 (추천 수락 포함) | 콘솔 + 알림톡 | P2 |
| 배차 확정·거절·만료 | 차주 | 주선사 응답 또는 10분 경과 | 앱 푸시 (주행 중 음성) | P2 |
| 조건 맞는 새 오더 | 차주 | 저장한 조건에 맞는 오더 등록 | 앱 푸시 (주행 중 음성 한 줄) | P2 |
| 결제 예정·실패 | 차주, 주선사 | 정기결제 3일 전, 결제 실패 | 알림톡 | P3 |
| 미수금 알림 | 차주 | 지급 예정일 경과 | 앱 푸시 (다음 시동 때 음성) | P2 |
| 가족 안심 공유 | 차주가 지정한 가족 | 운행 시작·귀가 예정 | 알림톡 | P3 |

## 기능 요구사항

| ID | 요구사항 | 우선순위 |
|---|---|---|
| NOTI-001 | 도메인은 `발송 요청(종류, 받는 사람, 변수)`만 보내고, 채널 선택과 템플릿 적용은 알림 도메인이 한다 | P1 |
| NOTI-002 | 1차 데모는 SMS로 보내고, 2차 PT 전까지 카카오 알림톡으로 바꾼다. 알림톡 실패 시 SMS로 대신 보낸다 | P1 |
| NOTI-003 | 같은 운행·같은 종류의 발송은 정해진 간격 안에 다시 보내지 않는다 (예: ETA 재알림 30분) | P1 |
| NOTI-004 | 모든 발송을 기록한다: 종류, 받는 사람, 채널, 결과, 시각 | P1 |
| NOTI-005 | 밤 10시~아침 7시에는 수하인에게 보내지 않는다. 주선사는 설정을 따른다 | P2 |
| NOTI-006 | 받는 사람의 전화번호는 운행이 끝나고 30일 뒤 지운다 | P2 |
| NOTI-007 | 발송은 서버에서 비동기로 처리한다. 외부 발송 서비스 장애가 다른 기능을 막지 않는다 | P1 |

## 데이터

| 엔티티 | 주요 필드 |
|---|---|
| NotificationRequest | id, type, tripId?, recipientType, recipientPhone, variables(JSON), requestedAt |
| NotificationLog | id, requestId, channel(ALIMTALK/SMS/PUSH), status(SENT/FAILED), providerMessageId?, sentAt, error? |
| NotificationTemplate | type, channel, templateCode, body |

## 미결 사항

- [ ] 발송 서비스 선정 (NHN Cloud, 솔라피 등). 알림톡은 카카오 비즈니스 채널과 템플릿 심사가 필요하므로 일찍 신청
- [ ] 1차 데모용 SMS 발송 비용과 테스트 번호

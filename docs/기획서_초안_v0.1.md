## 1. 한 줄 소개

**운전대에서 손을 떼지 않고, 오더를 잡고·달리고·돈을 받기까지 끝내는 화물차 전용 차량용 앱**

기존 화물 앱은 "오더를 잡는 앱"에서 끝납니다. Ieo는 **오더 마켓(화물 정보망)**이면서, 배차를 받은 뒤 **운행이 끝날 때까지의 과정과 공차 없이 다음 일로 이어지는 과정**까지 맡습니다. 차량 위치·주행 상태·경로 데이터를 직접 쓸 수 있는 차량 환경이 아니면 만들 수 없는 서비스입니다.

- **오더 마켓:** 주선사가 오더를 올리고, 차주가 Ieo에서 찾아 배차를 요청함. 오더 보기와 배차는 회비 없이 무료
- **운행 비서:** ETA 자동 알림, 대기 자동 기록과 대기비 증빙, 전자인수증, 자동 장부, 세금계산서 자동 발행. 다른 앱이나 전화로 받은 일에도 똑같이 동작함

## 2. 문제 정의 (Pain Points)

| # | 문제 | 근거 |
|---|---|---|
| P1 | **오더를 찾는 데 하루 수 시간을 쓰고, 그 과정에서 운전 중에도 폰을 조작함** | "오더앱만 하루 4시간"이라는 차주 후기(아틀란트럭). 선착순 클릭 경쟁, 매크로('지지기') 사용 보도 |
| P2 | **하차 후 다음 일을 못 잡아 빈 차로 달림** | 공차율 약 41%(2017, 국가교통조사). 미국 27%, 영국 28.7%보다 높음 |
| P3 | **상하차 대기 시간을 돈으로 받지 못함** | 1시간 이상 대기 64%, 대기료 미반영 81%(상용차매거진 2025.4, n=281). 운전 외 업무 하루 4.5시간(한국교통연구원) |
| P4 | **주선사·수하인의 "어디쯤이세요?" 전화** | 운전 중 통화가 반복됨 `[TODO: 아버님 인터뷰로 하루 몇 통인지 확인]` |
| P5 | **정산 지연과 증빙 부족** | 1개월 넘게 받지 못한 운임 30~40%(2013). 종이 인수증 분실. 대기비는 증빙이 없어 청구하기 어려움 |

**핵심 인사이트.** 기사의 수입은 "얼마나 쉬지 않고 다음 일로 이어 가느냐"와 "일한 시간을 얼마나 빠짐없이 돈으로 받느냐"로 결정됩니다. 그런데 기존 앱은 오더 목록만 보여줄 뿐, **운행 중인 기사의 맥락(지금 어디쯤인지, 몇 시에 끝나는지, 얼마나 기다렸는지)을 모릅니다.**

## 3. 타깃 고객

- **1차 타깃: 차주(개인 화물차 기사)**
  - 정보망 앱을 쓰는 차주 약 16만~17만 명 `[가정: 커넥터스 추정치]`
  - 평균 연령이 소형 65.5세, 대형 58.7세로 높음. 화면 조작보다 **음성과 자동화**가 맞는 사용자층
  - 페르소나: 50대 후반, 5톤 카고, 경기~영남 노선, 앱 2~3개 동시 사용 `[TODO: 아버님 실제 프로필로 교체]`
- **2차 타깃: 주선사(운송주선업체)**
  - 오더를 올릴 곳과 믿을 만한 차주가 필요함
  - 배차한 차량의 위치와 도착 예정 시간을 전화 없이 알고 싶어 함
  - 대기비를 화주에게 청구할 증빙과, 견적에 쓸 실제 운임·소요 시간 데이터가 필요함

## 4. 핵심 기능

### 기본: Ieo 오더 마켓 (P1)

- 주선사가 웹 콘솔에 오더를 올림. 무게, 상하차 방식(지게차 유무), 결제 방식, 지급 예정일까지 **필수로 입력해야 등록**됨 → 부정확한 오더 정보 문제를 등록 단계에서 막음
- 차주는 정차 중 목록·지도로, 주행 중에는 "근처 오더 있어?"라고 물어 음성으로 오더를 찾음
- 오더 카드에 **실수익**, **노선 최근 평균 운임**, **주선사 지급 이력**이 함께 보임 → 깎인 오더와 지급이 늦은 주선사를 스스로 거를 수 있음
- **선착순 클릭 경쟁 대신 "요청 → 주선사 확정"** 방식. 운전 중 화면 조작과 매크로('지지기')를 부르는 구조를 없앰
- 재위탁(다단계) 오더 신고와 탐지, 불법 행위 고지 → 2027.9 플랫폼법의 플랫폼 의무에 대응
- Ieo는 정보만 제공하고 계약은 주선사와 차주가 맺음 (운송주선사업 허가 없는 중개·대리 금지 조항 준수)
- 상세: [requirements/11_배차.md](requirements/11_배차.md)

### 기능 ① 당일 하차 예정 시간 자동 알림 (P4)

- 배차를 등록하면 NaviHelper의 경로 정보와 실시간 위치로 **하차 도착 예정 시간(ETA)을 계산**함
- 출발, 중간 지점, 30분 전, 도착 시점에 주선사와 수하인에게 **자동 알림** (카카오 알림톡 또는 SMS)
- 막히거나 휴게소에 들러서 ETA가 15분 넘게 바뀌면 자동으로 다시 알림
- 기사 화면 조작은 0회. 결과적으로 "어디쯤이세요?" 전화가 사라짐

### 기능 ② 운행 진행률 기반 다음 배차 추천 (P1, P2)

- 현재 운송의 **진행률이 1/2, 2/3 지점에 오면** 다음 배차 탐색을 시작함
- 추천 조건
  - 하차지 반경 N km 안의 상차지
  - 예상 하차 완료 시각(ETA + 하차 작업 시간)과 맞는 상차 시간
  - 내 차량의 톤수·차종에 맞는 화물
  - **실수익** 순으로 정렬. 실수익 = 운임 − 공차 이동 연료비 − 통행료
- **주행 중에는 음성으로만 안내함** (TTS)
  - "하차지 근처 평택에서 오후 3시 상차, 대구행 5톤, 실수익 28만 원 건이 있습니다. 들어볼까요?"
  - 기사가 "수락" 또는 "다음"이라고 말하면 처리됨 (STT)
- 정차 중(Vehicle SDK로 기어 P나 속도 0 감지)에만 상세 화면을 보여줌
- **최종 결정은 기사가 함.** 자동배차가 단가를 떨어뜨린다는 반감을 반영한 설계

### 기능 ③ 상하차 대기 시간 자동 기록과 대기비 증빙 (P3, P5)

- 상차지·하차지 반경 안으로 들어오면(지오펜스) **대기 타이머가 자동으로 시작**됨
- 차량이 출발하면(Vehicle SDK의 주행 상태) 타이머가 자동으로 끝남
  - 기사가 "상차 시작" 버튼을 누르거나 음성으로 말하면 대기와 작업 시간을 나눠 기록함
- 대기비 정책은 주선사·화주별로 설정함 (예: 2시간 초과 후 30분당 N원)
  - 설정에 따라 **청구 가능한 대기비를 자동 계산**함
- **대기 증빙 리포트**: 도착 시각, 출발 시각, 위치 이력, 지도를 담은 PDF나 링크를 주선사에게 바로 전송함
- 쌓인 데이터로 "이 상차지는 평균 대기 2시간 10분" 같은 **상하차지 대기 지도**를 만들고, 기능 ②의 추천에 반영함

### 기능 ④ 전자인수증 (P5)

- 하차 30분 전에 수하인에게 가는 ETA 알림(기능 ①)에 **인수 확인 링크**를 함께 보냄
- 하차가 끝나면 수하인이 자기 폰에서 서명함 → 시각·위치·하차 사진이 묶인 전자인수증이 생성됨
- 주선사에게 바로 전달됨. 종이 인수증 분실, 우체국 등기, 정산 지연이 사라짐
- 기사는 차량 화면에서 "인수증 받기" 버튼 한 번만 누르면 됨 (수하인 폰에 QR 표시)

### 기능 ⑤ 상하차지 정보 카드 (P1, 부정확한 오더 정보)

- 상하차지에 다가가면(반경 3km) 음성으로 안내함
  - 예: "이 상차지는 높이 제한 3.5m, 지게차 있음, 평균 대기 1시간 20분입니다."
- 정보는 두 경로로 쌓임
  - 기능 ③의 자동 데이터: 평균 대기 시간
  - 기사의 **음성 메모**(STT): "지게차 기사 점심시간 12~1시" 같은 팁
- 기능 ②의 다음 배차 추천에도 반영됨 (대기가 긴 상차지는 실수익을 낮게 계산)

### 기능 ⑥ 연속 운전·휴게 관리 (안전)

- Vehicle SDK로 연속 주행 시간을 측정함
- 휴게 의무 시점이 다가오면 경로상 다음 휴게소를 음성으로 안내함 `[확인 필요: 화물자동차 운수사업법상 "2시간 연속 운전 시 15분 이상 휴게" 기준]`
- 휴게 시간은 기능 ①의 ETA와 기능 ②의 추천 시간 계산에 자동으로 반영됨
- 쉬면 다음 일을 놓친다는 압박('탕바리')을 줄이고, 안전 운전을 앱이 뒷받침함

### 기능 ⑦ 하루 마감 수익 리포트 (P2, P3)

- 시동을 끄면(그날 마지막 운행 종료 시) 하루 요약을 음성과 화면으로 보여줌
  - 운행 건수, 총운임, 실수익(연료비·통행료 차감)
  - 공차 거리와 공차율, 대기 시간과 청구 가능한 대기비
- 월별 추이를 볼 수 있음. 세금 신고용 운행 기록으로 내보낼 수 있음
- 기사가 매일 앱을 켤 이유가 생김 (리텐션)

### 기능 ⑧ 주선사 신뢰 지표 (다단계, 미지급)

- 실제 운행 데이터로 주선사마다 지표를 계산함
  - 평균 지급 소요일, 대기비 지급 여부, 평균 대기 시간
- 기사는 다음 배차 추천(기능 ②)에서 주선사 지표를 함께 확인함
- 별점처럼 주관적인 평가가 아니라 **운행 데이터 기반**이라 조작하기 어려움
- 2027.9 시행되는 플랫폼법의 허위매물·미지급 관리 의무에 대응하는 기능이기도 함

### 기능 ⑨ 자동 장부 (운임·경비·미수금)

- **배경**: 실제 차주(아버님)는 운행 내역을 종이 메모장에 직접 적고 있음 `[TODO: 메모장 사진과 기록 항목 확보]`
- **기존 서비스와의 차이** (2026.10 조사)
  - 정보망 앱(화물맨, 카카오T 트럭커)은 **자기 앱에서 잡은 오더**의 배차·정산 내역만 보여줌. 여러 앱과 전화로 받은 일을 한데 모은 장부는 없음
  - 장부 전용 앱(예: [화물 장부](https://apps.apple.com/us/app/-/id6755648857))은 운임·미수금·통계를 지원하지만, 운행이 끝난 뒤 **폰으로 직접 입력**해야 함
- **Ieo의 방식: 운행이 곧 장부**
  - 배차 등록(음성, 링크, 직접 입력) → 운행 → 하차가 끝나면 장부 한 줄이 **자동으로** 생성됨
    - 자동으로 채워지는 항목: 날짜, 상하차지, 실제 주행거리(Vehicle SDK), 대기 시간(기능 ③), 운임, 주선사
  - 경비는 운전 중에 음성으로 기록함: "주유 15만 원", "통행료 2만 3천 원", "식대 9천 원"
  - **미수금 관리**: 결제 방식(선불/착불/인수증)과 지급 예정일을 기준으로 미수금을 추적함. 예정일이 지나면 음성으로 알려줌. 이 데이터가 기능 ⑧(주선사 신뢰 지표)의 원천이 됨
  - 월별·거래처별 매출, 실수익, 종합소득세·부가세 신고용 엑셀 내보내기
- 입력 부담이 거의 없어서 **고령 기사도 메모장을 대신해 쓸 수 있음**. 매일 쓰는 기능이라 리텐션의 핵심이 됨

## 5. 차량특화성: 왜 폰이 아니라 차량 앱인가

| 항목 | 모바일 앱 | 차량 앱 (Ieo) |
|---|---|---|
| 주행 상태 인지 | 추정만 가능 (GPS 속도) | 기어, 속도, 시동 상태를 정확히 알 수 있음 → 대기·작업·운행을 정확히 구분 |
| 운전 중 사용 | 화면 조작 위험 | 차량 스피커와 마이크로 음성 처리. 화면은 정차 중에만 |
| 경로·ETA | 별도 내비 앱과 연동 안 됨 | NaviHelper로 현재 길 안내 경로와 ETA를 직접 사용 |
| 화면 | 내비와 번갈아 봐야 함 | Pleos 2창 화면에서 내비 옆에 Ieo를 나란히 띄움 |
| 데이터 신뢰도 | 폰을 두고 내리면 끊김 | 차량에 붙어 있어 대기 증빙의 신뢰도가 높음 |
| 항상 켜져 있음 | 배터리와 백그라운드 제한 | 시동이 켜져 있는 동안 항상 동작 |

## 8. 사업성

### 시장의 돈 흐름 (화물맨 사례)

화물 정보망은 운임 흐름에 끼지 않고, **오더를 올리는 쪽과 보는 쪽 모두에게 이용료**를 받는다 ([research/01](../research/01_화물중개앱_시장조사.md) 2-1).

| 대상 | 화물맨 요금 | 얻는 것 |
|---|---|---|
| 차주 | 정액제 월 22,000~55,000원(가입비 3만 원) 또는 정량제 배차 1건당 5,000원 | 오더 열람·배차 (일을 받기 위한 **입장료**), 정회원 금융·복지 혜택 |
| 주선사 | 일반회원 무료, 정회원 월 33,000원 | 정회원은 공유 화물 기능으로 실시간 운송료 단가·전국 물동량 확인 |

- 기사님들은 일을 놓치지 않으려 앱 2~3개에 회비를 중복으로 냄
- 2027.9 플랫폼법은 **계약 건마다 받는 중개수수료를 금지**함. 화물맨 정량제 같은 건당 요금은 영향을 받을 수 있음

### 수익 모델: 차주·주선사 양쪽 플랜

원칙은 세 가지임.
1. **오더 보기와 배차는 모든 플랜에서 무료.** 기존 정보망의 입장료를 받지 않음 → 차주가 모이고, 차주가 모여야 주선사가 오더를 올림
2. **돈과 직결되는 기능에 과금.** 세금계산서, 대기비 증빙, 장부, 세무·금융 연계
3. **월정액 구독만.** 건당 요금이 없어 플랫폼법에 맞음

## 9. 물량(오더) 확보 전략

> 기존 신규 플랫폼(KT 브로캐리, LG U+ 화물잇고)은 "오더 마켓"만으로 시작했다가 물량을 확보하지 못해 철수함.
> Ieo도 오더 마켓이지만, **운행 비서 기능으로 차주를 먼저 모으고** 그 차주와 운행 데이터로 주선사를 끌어와서 이 닭과 달걀 문제를 피함.

### 9-1. 핵심 전략 A: 물량 없이도 첫날부터 쓸모 있는 앱
- 기능 ①(ETA 알림), ③(대기 기록), ④(전자인수증), ⑤(상하차지 정보), ⑥(휴게 관리), ⑦(수익 리포트), ⑨(자동 장부)는 **오더가 0건이어도 동작함**
- 기사는 어느 정보망에서 잡은 배차든 그대로 등록하면 됨
  - 등록 방법: 음성("평택 삼성 상차, 대구 하차"), 주선사가 보낸 링크, 직접 입력
- 처음에는 **기존 앱 위에 얹어 쓰는 앱**으로 들어가서, 차주가 가입할 때 기회비용이 없음. 오더 마켓의 물량이 쌓이면 Ieo 안에서 배차까지 받게 됨
- 오더 보기는 무료라, 기존 앱처럼 회비를 내야 일을 볼 수 있는 진입 장벽이 없음

### 9-2. 핵심 전략 B: 주선사가 스스로 들어오게 만들기
- 주선사의 고통
  - 화주의 "차 어디쯤이에요?" 문의
  - 대기비를 화주에게 청구할 증빙이 없음
  - 인수증 회수 지연으로 화주 정산도 늦어짐
- Ieo를 쓰는 차주에게 배차하면 **위치·ETA 자동 공유, 대기 증빙, 전자인수증을 무료로** 받을 수 있음
- 주선사가 오더를 콘솔에 올리기 시작하면 → 그 오더가 **Ieo 오더 마켓과 기능 ②(다음 배차 추천)의 물량이 됨**
- 오더 등록은 무료로 열어 두고, 운행 데이터 리포트에 정회원 요금을 받음
- 선순환: 차주 증가 → 주선사 유입 → 오더 증가 → 추천 품질 향상 → 차주 증가

### 9-3. 실행 근거 C: 좁고 깊게 시작하기
- 실제 차주(아버님)가 거래하는 주선사 N곳과 주력 노선 1개에서 시작해 밀도를 만듦
- `[TODO: 아버님 거래 주선사 중 파일럿 의향이 있는 곳 확인 → "주선사 N곳 파일럿 의향 확보"를 기획서와 PT에 명시]`

### 9-4. 확장 비전 D: 현대차그룹 시너지
- 현대 상용차(포터·마이티·엑시언트) + Pleos Connect + 그룹 물류 물량을 잇는 차량 기반 화물 운행 플랫폼
- 우리가 통제할 수 없는 영역이므로 비전으로만 제시함

### 9-5. 규제 대응
- 2027.9 시행되는 화물운송플랫폼법 대응 (2026.9.22 공포, 법률 제21970호)
  - 운송플랫폼사업 **등록제**: 정식 출시 시 국토부에 등록 (플랫폼 보안조치, 사업계획, 사무실 요건)
  - **건당 중개수수료 금지**: 차주·주선사 모두 월정액 구독만 받음
  - **무허가 중개·대리 금지**: Ieo는 정보만 제공하고, 계약은 주선사의 배차 확정으로 성립
  - **불법 행위 고지·신고·이용 제한 의무**: 오더 등록 필수 항목, 재위탁 탐지, 신고 기능, 기능 ⑧(주선사 신뢰 지표)로 데이터 기반 관리
  - 기존 정보망이 새로 갖춰야 할 의무를 Ieo는 처음부터 설계에 넣음

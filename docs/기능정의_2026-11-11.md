# 이에오(Ieo) 기능 정의 — 2026-11-11 구현 기준

공모전 접수양식 "02 앱 프로젝트 소개"의 **3. 주요 기능 및 차량 특화 요소**, **5. 개발 계획(SDK/API 활용)** 에 옮겨 쓰기 위한 정리. 기획서 초안(`기획서_초안_v0.1.md`)이 기획 시점 기준이라면 이 문서는 **지금 코드에 있는 것** 기준이다.
근거: 차량 앱 `android/app/src/main/java/com/ieo/app`, `docs/design/05_차량앱_구조.md` 7장, 서버 `ieo-server`, 콘솔 `ieo-console`.
2026-11-12에 세 저장소의 최신 코드와 다시 대조해 고쳤다 (배차 추천 단순화, 도착·떠남 확인 창, 운행당 하나인 대기 증빙, 휴게 안내, 배차 취소 패널티 반영).

상태 표기: **완성** = 서버와 연결돼 동작 확인 / **일부** = 핵심은 되고 일부 항목이 빠짐 / **기획** = 문서에만 있음.

## 1. 한눈에 보기

| 구성 | 누가 쓰나 | 무엇 |
|---|---|---|
| **차량 앱** (Pleos Connect, Android) | 화물차 기사(차주) | 운행 진행, 휴게 안내, 대기 증빙, 다음 배차 추천, 오더 마켓, 장부(인수증 보냈는지·사진) |
| **주선사 웹 콘솔** (React) | 운송주선사 담당자 | 오더 등록·배차 확정, 운행 위치·ETA, 단골 차주, 담당자, 리포트, 회사 서류 |
| **운영자 페이지** (콘솔 안 /admin) | 이에오 운영자 | 차주·주선사 서류 심사, 국세청 진위확인 |
| **공개 웹 페이지** (서버 정적) | 주선사, 화주 | 대기 증빙 열람 (앱 설치 없이 링크·QR) |
| **서버** (Spring Boot, PostgreSQL) | 위 전부 | 상태 관리, 계산(ETA·대기비·실수익·추천·지표), 알림(SSE), 공개 링크 |

차량 앱 탭은 **홈 / 오더 / 장부 / 설정** 4개. 홈은 서버의 운행 상태에 따라 운행 전 → 주행 중 → 대기 중 화면으로 바뀐다.

## 2. 차량 앱 기능

### 2-1. 운행

| 기능 | 하는 일 | 차량 특화 요소 | Pleos SDK / 차량 API | 상태 |
|---|---|---|---|---|
| 차량 로그인 | 차량 화면에 뜬 QR을 휴대폰으로 찍어 승인. 인증번호 로그인도 됨. 토큰은 Keystore 암호화 저장 | 차량 키보드 없이 로그인 | — | 완성 |
| 트럭과 내 차량 잇기 | 홈에 들어올 때 차대번호(VIN)를 읽어 서버의 내 차량과 자동 연결. 여러 대면 고르는 창 | 어느 트럭에 탔는지 앱이 스스로 안다 | Vehicle SDK `getCarInfo().getVINInfo` | 완성 (실차 VIN 미확인) |
| 실측 연비 반영 | 트럭의 누적 연비를 읽어 서버에 보냄. 오더 실수익(운임 − 기름값 − 통행료) 계산에 씀 | 기사가 연비를 추정해 넣을 필요 없음 | Vehicle SDK `getFuel().getCumulativeFuelEconomy` | 완성 (실차 값 미확인) |
| 운행 등록 (다른 앱·전화로 받은 일) | 상하차지를 "지금 여기 / 다녀온 곳 / 내비 즐겨찾기·최근 목적지"에서 고름. 시각은 오늘·내일 + 30분 단위, 운임·결제·주선사 칩 | 키보드 없이 내비 데이터로 등록 | NaviHelper `getBookmarkInfo`, `getRecentDestinationInfo`, `getCurrentLocationInfo` | 일부 (주소 검색 없음) |
| 상차지 → 하차지 길 안내 | "안내 시작"으로 상차지 안내. 상차를 마치고 떠나면 하차지 안내를 자동 요청 | 차량 순정 내비에 바로 목적지를 넣음 | NaviHelper `requestRoute`, `cancelRoute`, `onDestinationArrived` | 완성 |
| ETA·진행률 | 내비의 남은 거리·시간으로 도착 예정 시각과 진행률을 홈에 표시 | 내비 값을 직접 받아 휴대폰 지도보다 정확 | NaviHelper `onDrivingInfo`, `onDestinationInfo` | 완성 |
| 위치·ETA 공유 | 출발한 운행 동안 5분마다 GPS 위치와 내비 남은 거리·시간을 서버로. 끊기면 240개까지 쌓았다가 묶어 전송. 주선사 콘솔에 위치·ETA·진행률로 보임 | 내비 앞에 있어도 포그라운드 서비스로 계속 | GPS + NaviHelper | 완성 |
| 도착 예정 문자 | 출발 때, 진행률 50%, 도착 30분 전에 주선사에게 도착 예정 시각을 알림. 예정 시각이 15분 이상 바뀌면 30분에 한 번까지 다시. 차주가 주선사 공유 동의를 켰을 때만 | 내비의 남은 시간으로 시점을 정함 | NaviHelper | 일부 (문자는 로그만, 발송사 미정) |
| 휴게 안내 | 연속 운전 1시간 45분에 미리, 2시간에 경고 음성(연장운행은 2시간 45분·3시간). 15분 쉬면 다시 셈(2시간을 넘겼으면 30분). 경로 위 화물차 라운지·졸음쉼터를 받아 "다음 화물차 라운지" 카드로 보이고, 세워 두었을 때 라운지를 골라 "경유지로 안내" | 속도 신호로 연속 운전 시간을 세고, 쉴 곳을 내비 경유지로 넣음 | `CarPropertyManager` `PERF_VEHICLE_SPEED`, NaviHelper `addWaypoint`, TTS | 일부 (ETA에 휴게 시간 가산 없음) |
| 배차 확정 알림 | 주선사가 확정·마감하면 SSE로 받아 음성 + 화면 배너, 홈 갱신. 끊기면 재접속, 놓친 알림은 마지막 id부터 | 화면을 보지 않아도 음성으로 앎 | TTS | 완성 |

### 2-2. 상하차 대기와 증빙

| 기능 | 하는 일 | 차량 특화 요소 | Pleos SDK / 차량 API | 상태 |
|---|---|---|---|---|
| 도착 감지와 확인 | 상하차지 반경 안에서 세워 둔 채(기어 P 또는 주차 브레이크) 3분이면 "도착하셨어요? ○시 ○분부터 대기로 기록할까요?"를 음성과 화면으로 15초 물음. "맞아요"(터치·음성)면 **멈추기 시작한 시각**으로 대기 시작. 내비 도착 알림도 같은 확인을 띄움. 3km 안에서는 "대기 시작" 버튼으로 바로 시작 | 기어·주차 브레이크 신호로 알아채고 한 번만 확인 | `CarPropertyManager` `GEAR_SELECTION`, `PARKING_BRAKE_ON` | 완성 |
| 떠남 감지와 확인 | 반경 밖 30초 또는 20km/h 이상 1분이면 "출발할까요?"(하차지는 "운행을 마칠까요?")를 15초 물음. 맞다고 하면 그 시작 시각으로 떠남 기록. 상차지면 하차지 안내, 하차지면 운행 완료. 아니라고 하거나 대답이 없으면 반경에 다시 들어올 때까지 묻지 않음 | 속도 신호와 위치로 알아챔 | `CarPropertyManager` `PERF_VEHICLE_SPEED`, GPS | 완성 |
| 대기 기록 보관 | 도착·상차 시작·떠남 기록에 누른 순간·위치·방법(확인 창 터치·음성, 버튼)을 남김. 통신이 끊기면 앱에 쌓아 두고 15초마다 다시 보냄. 앱을 다시 켜도 남음 | 음영 지역에서도 시각이 틀어지지 않음 | — | 완성 |
| 대기 타이머·대기비 | 무료 대기가 끝나면 주선사의 대기비 정책(무료 분·단위·단가·상한·올림)대로 화면에서 계산. "상차 시작"으로 작업 시간 구분 | 대기 시각이 차량 데이터라 분쟁 근거가 됨 | — | 완성 |
| 대기 증빙 | 운행당 하나(상차지·하차지 대기를 함께 담음). 하차지에서 떠남을 확인하면 "대기 증빙을 만들까요?"를 묻고, 운행 완료 창의 체크나 장부에서도 만들 수 있음. 링크를 QR·주소로 표시, 열어 둔 페이지는 1분마다 갱신, 30일 뒤 만료. 주선사에게 바로 보내기 | 차량 화면 QR로 현장에서 건넴 | — | 완성 (PDF 없음) |
| 상하차지 정보 카드 | 도착하면 높이 제한(내 차 높이와 비교)·지게차·주차·평균 대기·메모. 3km 전에 음성 요약, 높이 안 맞으면 경고 | 접근 전 음성 경고 | TTS | 일부 (음성 메모 남기기 없음) |
| 인수증 | 결제 방식이 인수증인 운행만. 하차지에 도착한 뒤 휴대폰으로 종이 인수증을 찍어(5장까지) [주선사에게 보내기]. 주선사에게 문자, 콘솔에 사진. 보낸 날부터 지급 예정일. 차량 앱은 운행을 마칠 때 알리고 장부에 "인수증 보냄"과 사진 | 운행을 마칠 때 음성으로 알림 | TTS | 완성 (수하인 서명은 2026-11-12 뺌) |

### 2-3. 다음 배차 추천과 음성

### 2-6. 계정·차량·안전

| 기능 | 하는 일 | 상태 |
|---|---|---|

## 6. 차량 특화 요소 (기획서 문장용)

1. **ETA·진행률·도착 알림이 차량 순정 내비 값으로 돌아간다.** 남은 거리·시간을 NaviHelper에서 직접 받아 진행률, 도착 예정, 주선사 공유와 도착 예정 문자 시점(출발·50%·도착 30분 전)을 정한다. 휴대폰 지도로는 이 값을 못 받는다.
2. **상하차 대기가 차량 신호로 기록된다.** 반경 안에서 세워 둔 채(기어 P 또는 주차 브레이크) 3분이면 도착을, 반경 밖 30초 또는 20km/h로 1분이면 떠남을 알아채 기사에게 한 번 확인받는다. 대기비 증빙의 시각이 기사가 적은 값이 아니라 차량 데이터가 된다.
3. **트럭이 스스로 신원을 밝히고 연비를 알려 준다.** VIN으로 차량을 자동 연결하고 누적 연비를 읽어 오더별 실수익을 계산한다.
4. **달리는 중엔 말로 대답한다.** 도착·떠남·대기 증빙 확인을 "네/아니요"로 끝낸다. 기기 안 음성 인식을 쓰고, 음악은 줄이고 내비 음성은 기다린다.
5. **차를 세웠는지에 따라 화면이 바뀐다.** 달리는 중엔 정보와 음성 확인만, 세워 두었을 때(기어 P 또는 주차 브레이크)만 다음 배차 추천·휴게소 목록 같은 선택지를 띄운다. 큰 글자·큰 버튼, 분할 화면 레이아웃.
6. **차량 화면이 현장 단말이다.** 대기 증빙을 QR로 건네고, 로그인·운행 등록도 키보드 없이 한다. 종이 인수증은 휴대폰으로 찍어 보내고 차량 장부에서 확인한다.
7. **쉴 때를 차가 알려 준다.** 속도 신호로 연속 운전 시간을 세어 2시간이 되기 전에 음성으로 알리고, 경로 위 화물차 라운지를 내비 경유지로 넣는다.

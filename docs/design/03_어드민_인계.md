# 어드민 페이지(주선사 웹 콘솔) 인계

이 문서는 주선사가 쓰는 웹 콘솔(이하 "어드민 페이지")을 만들 개발자를 위한 출발점이다. 2026-11-03 기준이다.

- 서버에 있는 주선사 기능과 빠진 기능의 상세: [02_주선사_인계.md](02_주선사_인계.md)
- 주선사 요구사항: [../requirements/07_주선사.md](../requirements/07_주선사.md), 오더·배차: [../requirements/11_배차.md](../requirements/11_배차.md)

> "어드민"은 여기서 **주선사 회사가 쓰는 콘솔**을 말한다. Ieo 운영자가 쓰는 내부 관리 화면(신고 처리, 회원 정지 등)은 아직 요구사항이 없고 이 문서의 범위가 아니다.

## 1. 프로젝트 한눈에 보기

**이에오(Ieo)** 는 화물차 기사(차주)를 위한 차량 안 비서이자 오더 마켓이다. 현대자동차그룹 차량 앱 공모전(Pleos Connect, 2026) 개인 출품작이다.

- **오더 마켓:** 주선사가 오더(화물 운송 건)를 올리면 차주가 차량 화면에서 보고 배차를 요청하고, 주선사가 확정한다.
- **운행 비서:** 확정된 운행의 길 안내, 상하차지 대기 시간 기록과 대기비 계산, 전자인수증, 자동 장부를 차량에서 처리한다. 차량의 기어·속도·경로를 알기 때문에 기사가 손대지 않아도 주행과 대기를 구분한다.

사용자는 두 종류다.

| 사용자 | 쓰는 곳 | 하는 일 |
|---|---|---|
| 차주 (`DRIVER`) | 차량 앱 (Android Automotive) | 오더 찾기·요청, 운행, 대기 기록, 인수증 받기, 장부 |
| 주선사 담당자 (`BROKER`) | **어드민 페이지 (이번 작업)** | 오더 등록, 배차 확정·취소, 대기비 정책, 진행 중 운행 확인 |

### 저장소

| 저장소 | 내용 | 기술 |
|---|---|---|
| [ieo-app](https://github.com/SeolHuiGwan9478/ieo-app) | 차량 앱(`android/`), 기획·요구사항·설계 문서(`docs/`), 브랜드(`design/`) | Kotlin, Jetpack Compose |
| [ieo-server](https://github.com/SeolHuiGwan9478/ieo-server) | API 서버. 차량 앱과 어드민 페이지가 함께 쓴다 | Spring Boot 4.1, Java 21, H2(로컬)·PostgreSQL |
| (새로 만듦) | 어드민 페이지 | React. 저장소 이름·위치는 새로 정한다 |

## 2. 어드민 페이지의 역할

주선사가 **스스로 Ieo에 오더를 올리게 만드는 것**이 목적이다. 여기서 올라온 오더가 차주 쪽 오더 마켓의 물량이 된다. 주선사 입장에서 얻는 것은 "기사에게 전화하지 않아도 위치·대기·인수 여부를 바로 안다"는 점이다.

사용 흐름 (요구사항 07 시나리오):
1. 배차 담당자가 가입하고 단골 차주를 전화번호로 초대한다.
2. 오더를 등록한다. 단골 차주에게 지정하거나 오더 마켓에 공개한다.
3. 차주들이 보낸 배차 요청을 보고 한 명을 확정한다. 확정하면 차주 앱에 운행이 생긴다.
4. 화주가 "어디쯤이냐"고 물으면 콘솔에서 위치와 ETA를 본다.
5. 대기가 길어지면 차주가 보낸 대기 증빙 링크를 화주에게 전달해 대기비를 청구한다.
6. 하차가 끝나면 전자인수증(수하인 서명)을 확인한다.

## 3. 화면 목록과 서버 준비 상태

**있음** = 서버 API가 동작함, **서버 필요** = 화면보다 서버 작업이 먼저다.

| 화면 | 내용 | API | 상태 |
|---|---|---|---|
| 로그인 | 휴대폰 인증번호 → 로그인 | `/api/auth/phone/code`, `/phone/verify`, `/phone/login`, `/refresh` | 있음 |
| 가입 | 담당자 정보 + 사업자 정보(상호, 사업자등록번호, 허가 번호) | `/api/auth/signup` | **서버 필요**: 지금은 `User`만 생기고 주선사 회사(`Broker`)·담당자(`BrokerMember`)가 안 생김 |
| 오더 목록 | 상태별 목록, 대기 중인 요청 수 | `GET /api/broker/orders?status&page&size` | 있음 |
| 오더 등록 | 상하차지, 시간, 화물, 톤수·차종, 운임, 결제 방식, 지정 차주 | `POST /api/broker/orders` | 있음 (수정 API는 없음) |
| 오더 상세 | 오더 정보 + 요청한 차주 목록(차량, 완료 운행 수, 늦은 취소 수) | `GET /api/broker/orders/{id}`, `/{id}/requests` | 있음 |
| 배차 확정·취소·내리기 | 요청 확정, 확정 뒤 취소(다시 모집 / 내리기), 오더 내리기 | `.../requests/{requestId}/confirm`, `/{id}/cancel`, `/{id}/close` | 있음 |
| 대기비 정책 | 무료 대기 시간, 단위 시간당 금액, 최대 금액, 올림 방식 | `GET` / `PUT /api/brokers/me/wait-policy` | 있음 (바꾸기는 대표만) |
| 진행 중 운행 | 지도·표: 차주, 상태, 현재 위치, ETA | 없음 | **서버 필요**: 주선사용 운행 API, 위치 기록·ETA 미구현 |
| 대기 증빙 보기 | 운행별 대기 시간·대기비 | `GET /api/public/wait-proofs/{token}` (로그인 없이). 차주가 보내는 링크는 페이지 `/w/{token}` | 링크는 있음, 운행에서 찾아가는 API는 서버 필요 |
| 전자인수증 보기 | 서명, 서명 시각, 이상 사항 사진 | `GET /api/public/delivery-proofs/{token}`, `/signature`, `/photos/{id}` | 링크는 있음, 운행에서 찾아가는 API는 서버 필요 |
| 담당자 관리 | 초대, 직책 변경, 내보내기 | 없음 | 서버 필요 |
| 단골 차주 | 초대, 연결 목록 | 없음 | 서버 필요 (`BrokerDriverLink`) |
| 회사 설정 | 정산 주기 | 없음 (`Broker.changeSettlementDays()`만 있음) | 서버 필요 |
| 리포트·신뢰 지표 | 노선·상하차지 리포트, 지급 지표 | 없음 | P3. 2차 PT는 샘플 데이터로 시연 |

**권장 순서:** 서버의 주선사 가입과 CORS → 로그인·가입 → 오더 목록·등록·상세·확정 → 대기비 정책 → 진행 중 운행(서버 작업과 함께). 서버에서 빠진 것의 상세와 구현 힌트는 [02_주선사_인계.md](02_주선사_인계.md) 2장에 있다.

## 4. 서버와 붙일 때 알아야 할 것

### 로컬 실행

```bash
cd ieo-server && ./gradlew bootRun
```

- `http://localhost:8080`. 기본 `local` 프로필은 `data/` 아래 H2 파일 DB를 쓴다. DB 확인은 `/h2-console`.
- 문자는 실제로 보내지 않는다. 인증번호는 서버 로그의 `[문자 발송]` 줄에서 본다.
- **CORS 설정이 아직 없다.** 개발 서버(예: `localhost:5173`)에서 부르면 브라우저가 막는다. 서버 `WebConfig`에 허용 주소를 설정 파일로 받게 추가하거나, 개발 중에는 Vite 프록시를 쓴다.

### 로그인과 토큰

설계: [01_로그인.md](01_로그인.md)

1. `POST /api/auth/phone/code` 로 인증번호를 보낸다.
2. `POST /api/auth/phone/verify` 가 `phoneToken`과 `accountExists`를 준다.
3. 계정이 있으면 `POST /api/auth/phone/login`, 없으면 `POST /api/auth/signup`(`role: BROKER`). 둘 다 `deviceId`가 필요하다. 브라우저에서는 처음 접속할 때 UUID를 만들어 저장해 두고 쓴다.
4. 응답은 `{ accessToken, refreshToken }`. 액세스 30분, 리프레시 30일.
5. 이후 요청은 `Authorization: Bearer {accessToken}`. 401이면 `POST /api/auth/refresh`로 새로 받는다.

- `/api/auth/**`, `/api/public/**` 만 로그인 없이 부를 수 있다.
- 이메일·비밀번호 로그인은 없다. 필요하면 서버와 함께 정한다.

### 응답 규칙

- **오류 형식은 하나다:** `{ code, message, fieldErrors }`. `code`는 `ORDER_404`, `ORDER_409_CONFLICT`처럼 도메인별이고, `message`는 화면에 그대로 보여 줘도 되는 한국어다. 입력값 검사 실패일 때만 `fieldErrors: [{ field, reason }]`가 찬다. 전체 목록은 서버 `global/error/ErrorCode.java`.
- **다른 회사 데이터는 404로 돌아온다.** 403이 아니다. "찾을 수 없음"으로 처리하면 된다.
- **동시 수정은 409:** 담당자 둘이 같은 오더를 동시에 확정하면 늦은 쪽이 `ORDER_409_CONFLICT`를 받는다. "다른 담당자가 먼저 처리했어요. 새로 고침해 주세요"를 띄운다.
- **화면 표기는 서버가 준다:** enum 옆에 `tonnageLabel`, `bodyTypeLabel`, `paymentTypeLabel` 같은 한국어 표기가 함께 온다. 콘솔에서 번역표를 따로 두지 않는다. 요청을 보낼 때는 enum 값(`TON_5`, `WING` 등)을 쓴다.
- **시각은 UTC(`Instant`, ISO-8601)로 오간다.** 화면에는 한국 시간으로 바꿔 보여 주고, 보낼 때도 UTC로 바꿔 보낸다.
- **상태 일부는 계산 값이다.** 예: 배차 요청은 10분이 지나면 `EXPIRED`로 내려오지만 DB에 저장된 값은 아니다. 목록을 다시 불러오면 바뀔 수 있다.
- 금액은 원 단위 정수다.

## 5. 디자인

차량 앱과 같은 브랜드를 쓴다. 로고·색 상세: [../../design/README.md](../../design/README.md)

- 로고: `design/logo/` 의 SVG를 그대로 쓴다. 흰 배경은 `*_orange.svg`, 주황·어두운 배경은 `*_white.svg`.
- **주황은 브랜드, 상태는 신호등.** 로고·주요 버튼·선택된 메뉴만 주황(`#FF6C37`, 버튼 `#F25A22`, 흰 바탕 위 글자 `#C2410C`). 운행은 파랑, 대기는 노랑, 완료·수익은 초록, 경고·미수금은 빨강.
- 바탕 `#F2F4F6` 위에 흰 카드, 제목 `#191F28`, 설명 `#8B95A1`.
- 차량 화면용 큰 글씨 규칙은 콘솔에는 적용하지 않는다. 일반 웹 크기로 만든다.

## 6. 같이 만들 수 있는 공개 웹 페이지

로그인 없이 링크로 여는 페이지다. 서버 API는 있고 화면만 없다. 콘솔과 같은 React 프로젝트에 둘지는 정해야 한다.

| 페이지 | 누가 여나 | API |
|---|---|---|
| 전자인수증 서명 | 수하인 (차량 화면의 QR을 휴대폰으로 찍음) | `GET /api/public/delivery-proofs/{token}`, `POST /sign` (캔버스 PNG data URL), `POST /photos` (multipart `file`, JPG·PNG 5MB, 5장까지) |
| 대기 증빙 | 주선사·화주 | `GET /api/public/wait-proofs/{token}` |

- 없는 토큰과 만료된 링크는 둘 다 404다. "링크가 만료되었어요"로 처리한다.
- 서명은 한 번만 할 수 있다. 다시 보내면 409.
- 상세 요구사항: [../requirements/04_인수증.md](../requirements/04_인수증.md), [../requirements/02_대기.md](../requirements/02_대기.md)

## 7. 정해야 할 것

- [ ] 어드민 페이지 저장소 위치와 배포 주소 (서버 CORS 허용 주소에 넣는다)
- [ ] 주선사 가입: 이미 등록된 사업자등록번호일 때 기존 회사에 합류하는 방법(초대)
- [ ] 콘솔 로그인 방식: 휴대폰 인증만 쓸지, 이메일·비밀번호를 추가할지
- [ ] 2차 PT 범위: 오더 등록·배차 확정·위치 확인만 실제로 동작하게 할지
- [ ] 차주 위치를 주선사에게 보여 주는 개인정보 동의 문구
- [ ] 공개 웹 페이지(인수증 서명, 대기 증빙)를 콘솔 프로젝트에 같이 둘지

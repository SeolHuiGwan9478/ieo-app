# 차량 앱 코드 구조

차량 앱(`android/app`)의 폴더 구조와 객체 사이의 역할을 정리한다. 서버 개발 관점에서 대응되는 개념을 같이 적었다. 2026-11-03 기준.

## 1. 한눈에 보기

요청 하나가 지나가는 길:

```
화면(Compose)  →  ViewModel  →  Repository(인터페이스)  →  Repository 구현  →  Retrofit API  →  서버
   그리기만         상태 관리       domain/                    data/              data/*/XxxApi
```

| 앱 | 하는 일 | 서버로 치면 |
|---|---|---|
| Compose 화면 (`ui/*Screen.kt`) | 상태를 받아 그리기만 한다. 버튼을 누르면 콜백을 부른다 | 뷰(HTML) |
| ViewModel (`ui/*ViewModel.kt`) | 화면 상태(`UiState`)를 들고, 사용자 동작을 받아 저장소를 부른다 | Controller + 화면용 상태 |
| Repository 인터페이스 (`domain/`) | "무엇을 할 수 있나"만 정한다 | Service 인터페이스 |
| Repository 구현 (`data/`) | 서버를 불러 결과를 앱 모델로 바꾼다 | ServiceImpl |
| Retrofit API (`data/*/XxxApi.kt`) | 서버 주소와 요청 모양 | 외부 API 클라이언트 (Feign) |
| DTO (`data/*/XxxDtos.kt`) | 서버 JSON과 같은 모양. `toDomain()`으로 앱 모델로 바꾼다 | Request/Response DTO |
| `di/AppContainer` | 객체를 만들고 서로 연결한다 | Spring의 Bean 설정 |

**규칙: 화살표 방향으로만 안다.** 화면은 ViewModel만 알고, ViewModel은 `domain/`의 인터페이스만 안다. 서버 통신(`data/`)은 바꿔 끼울 수 있다. 테스트에서 가짜 저장소(`FakeAuthRepository`)를 넣는 것도 이 덕분이다.

## 3. 새 기능을 붙이는 순서 (예: 설정)

1. `domain/account/`: 모델과 `AccountRepository` 인터페이스
2. `data/account/`: Retrofit API, DTO(`toDomain()`), `DefaultAccountRepository`
3. `di/AppContainer`: 저장소 한 줄 추가
4. `ui/settings/`: `SettingsUiState` + `SettingsViewModel`(+ `Factory`, `SettingsActions` 인터페이스) + `SettingsScreen`(상태만 받음) + `SettingsRoute`(둘을 잇는 곳)
5. 테스트: 가짜 저장소를 만들어 ViewModel을 시험 (예: `testing/FakeBooks`)

설정 탭(`ui/settings/`)이 바로 이 순서대로 만든 것이고, 장부 탭(`ui/ledger/`)도 같다.

## 4. 정해 둔 것

- **실패는 값으로:** 저장소는 예외 대신 `ApiResult`를 돌려준다. 화면은 `when`으로 성공과 실패를 모두 처리하고, 실패 문장은 `ApiError.message`를 그대로 보여 준다. 서버 오류 문장이 이미 한국어라서다.
- **로그인 이동은 세션이 정한다:** 로그인 성공, 로그아웃, 리프레시 토큰 만료 모두 `SessionManager.isLoggedIn`만 바뀌고, `MainActivity`가 그 값을 보고 화면을 바꾼다. ViewModel끼리 서로 부르지 않는다.
- **토큰 갱신:** 401이 오면 `TokenRefreshAuthenticator`가 한 번만 갱신한다. 서버가 리프레시 토큰을 거절하면 로그아웃하고, 서버에 닿지 못하면 로그인을 유지한다.
- **토큰 저장:** Android Keystore의 AES-GCM 키로 암호화해 저장한다. 키는 기기 밖으로 나가지 않는다.
- **서버 응답 변경에 강하게:** 모르는 필드는 무시하고(`ignoreUnknownKeys`), 모르는 enum이나 잘못된 날짜는 `mapResponse`가 `Unexpected`로 바꾼다. 앱이 죽지 않는다.
- **시간:** 서버 시각은 UTC(`Instant`)로 받고, 화면 표기는 한국 시각으로 바꾼다(`AssignedTripMapper`). 남은 시간 타이머는 기기 시계를 바꿔도 맞도록 `SystemClock.elapsedRealtime`을 쓴다.
- **의존성 주입 도구는 아직 쓰지 않는다:** `AppContainer`에서 손으로 연결한다. 객체가 많아지면 Hilt로 옮긴다.
- **모듈:** 지금은 Gradle 모듈 하나에 패키지로 나눴다. 패키지 경계가 위 규칙대로 지켜지고 있어서, 나중에 `:core`, `:data`, `:feature-login`처럼 Gradle 모듈로 쪼갤 때 폴더를 그대로 옮기면 된다.

## 6. 운행 진행 흐름

홈 화면은 서버의 운행 상태로 정해진다 (`HomeStateFactory`).

| 서버 운행 상태 | 홈 화면 | 다음으로 넘어가는 것 | 부르는 API |
|---|---|---|---|
| 진행 중인 운행 없음 | 운행 전: 내 배차 목록 | 배차를 눌러 "안내 시작" | `POST /api/trips/{id}/start` + 상차지 길 안내 |
| `TO_PICKUP` | 주행 중 (상차지로) | 반경 안 3분 정차, 내비 "목적지 도착", "도착했어요" 중 먼저 오는 것 | `POST .../stops/PICKUP/wait/arrive` |
| `AT_PICKUP` | 대기 중 → "상차 시작" → 상차 중 | "상차 시작", "상차 끝, 출발" 또는 자동 떠남 | `.../wait/work-start`, `.../wait/depart` + 하차지 길 안내 |
| `IN_TRANSIT` | 주행 중 (하차지로) | 반경 안 3분 정차 · 내비 도착 · "도착했어요" | `POST .../stops/DROPOFF/wait/arrive` |
| `AT_DROPOFF` | 대기 중 → 하차 중 | "하차 시작", "운행 완료" 또는 자동 떠남 | `.../wait/work-start`, `.../wait/depart` (서버가 운행 완료·장부 기록) |

- 앱을 껐다 켜도 `GET /api/trips/current`와 `GET /api/trips/{id}/waits`로 하던 화면을 이어서 보여 준다.
- 대기 타이머와 대기비는 서버 시각(도착, 대기비 시작, 작업 시작)을 기기 시계로 바꿔 화면에서 센다. 대기비 계산(`WaitPolicy`)은 서버와 같은 규칙이다.
- **도착:** 셋 중 먼저 오는 것. ① 반경 안 3분 정차(WAIT-001, 멈추기 시작한 시각을 보낸다) ② 내비 도착 알림 ③ "도착했어요" 버튼. 자동 도착으로 내비 안내를 끝내면 내비가 앞으로 나오므로, 잠시 뒤 이에오를 다시 앞으로 가져온다.
- **떠남:** 둘 중 먼저 오는 것. ① 자동 떠남(WAIT-005): 반경을 30초 넘게 벗어나거나(GPS가 튀는 것을 거른다) 20km/h 이상으로 1분 달리면, 벗어나거나 달리기 시작한 시각을 보낸다. 반경 밖에서 "도착했어요"를 누른 경우를 위해, 한 번이라도 반경 안에 들어온 뒤에만 반경 밖을 센다. 대기 화면에 남은 시간을 보여 준다 ② "상차 끝, 출발"·"운행 완료" 버튼. 작업 시작 전에 떠나도 된다(서버는 체류 시간만 남긴다).
- **에뮬레이터에서 시험하기:** 위치는 `adb emu geo fix <경도> <위도>`, 기어·속도는 가상 콘솔(`adb forward tcp:8088 tcp:8088` 뒤 `http://localhost:8088`, 페이지를 열어 둔 동안만 바뀐다). Pleos 내비 위치는 geo fix를 따르지 않는다.

## 7. 지금 서버와 연결된 것

| 화면 | 상태 |
|---|---|
| QR 로그인 | 연결됨: 서버 코드 → 2초마다 확인 → 승인되면 홈 |
| 휴대폰 로그인 | 연결됨. 가입된 차주 계정만 (차량에는 가입 화면이 없다) |
| 자동 로그인 | 저장된 토큰이 있으면 홈으로. 첫 요청에서 만료가 확인되면 로그인 화면으로 |
| 홈 "내 배차" | 연결됨: 끝나지 않은 운행을 상차 시각 순으로 |
| 운행 진행·대기 | 연결됨: 위 6장 |
| 자동 도착 | 연결됨 (WAIT-001): 가는 상하차지 반경 안에서 3분 정차(기어 P 또는 3km/h 미만)하면 멈추기 시작한 시각으로 도착을 보낸다. 주행 화면에 남은 시간을 보여 주고, 다시 달리거나 반경을 벗어나면 처음부터 센다. 속도·기어는 CarPropertyManager, 위치는 GPS. 처음 홈에 들어올 때 허락을 받는다. 내비 도착 알림·"도착했어요" 버튼도 그대로 쓴다 |
| 자동 떠남 | 연결됨 (WAIT-005): 반경 밖 30초 또는 20km/h 이상 1분이면 그 시작 시각으로 떠남을 보낸다. 상차지면 하차지로 길 안내, 하차지면 운행 완료. 대기 화면에 남은 시간을 보여 준다 |
| 홈 오늘 요약 | 연결됨: `GET /api/ledger/daily` (운행 수, 순수익) |
| 홈 미수금 경고 | 연결됨: `GET /api/ledger/receivables`에서 지급일이 지난 운임을 주선사별로 묶어 가장 오래 밀린 곳 하나 |
| 홈 오더 | 연결됨: `GET /api/orders?lat=&lng=` (내 차로 실을 수 있는 모집 중 오더 5건). 차량 위치(GPS)를 알면 상차지가 50km 안인 "근처 오더"와 상차지까지 거리를 보여 준다. 처음 위치가 들어올 때와 찾은 곳에서 5km 넘게 움직였을 때 다시 찾는다(운행 중에는 찾지 않는다). 위치를 모르면 "모집 중인 오더" 전체. 실수익·주선사 지급 소요일은 비워 둔다 |
| 오더 탭 | 연결됨: 위치를 알면 근처 오더(50km, 거리 표시), 날짜 칩(전체·오늘·내일), 확정 기다리는 내 요청 띠(10분 타이머, 철회), 상세, 배차 요청, 신고. 주행 중에는 목록을 감춘다 |
| 장부 탭 | 연결됨: 장부(월 요약 + 날짜별, 월 이동) · 미수금 · 경비. 받음 표시, 대기비 받음, 운임 고치기, 경비 추가, 운행 직접 추가 |

**링크:** 앱은 서버가 주는 `path`를 서버 주소 뒤에 붙여 QR에 넣는다.
- 인수증: `/r/{token}` 수하인 서명 페이지 (서버 `static/receipt.html`). 운행 정보, 이상 사항 메모·사진, 이름, 서명, 위치(선택)
- 대기 증빙: `/w/{token}` 주선사가 보는 증빙 페이지 (서버 `static/wait-proof.html`). 대기 중에도 만들 수 있고, 그때는 지금까지의 대기 시간·대기비를 1분마다 새로 보여 준다. 이탈하면 같은 링크에 최종 기록이 남는다. 기록을 고쳤으면 처음 값도 같이 보인다

홈의 샘플 데이터(`SampleHomeData`)는 이제 디버그 빌드의 "대기 샘플·주행 샘플"과 미리보기에만 쓴다.

## 8. 에뮬레이터에서 확인하는 순서

서버를 켜기 전에, 인증번호 하루 5번 제한에 걸렸으면 서버 저장소에서 `sh scripts/reset-sms-limit.sh`로 횟수를 0으로 되돌린다 (서버를 끈 상태에서).

1. **로그인·차량 잇기:** 휴대폰 로그인 → 홈에서 권한 허락 → 차량이 한 대면 "이 트럭을 ○○ 차량으로 연결했어요" 안내. 설정 탭 내 차량에 Pleos 연결 표시. 에뮬레이터가 차대번호를 주지 않으면 아무 안내도 없다
2. **근처 오더:** `adb emu geo fix 126.8337 36.9631`(평택 물류센터) → 홈 "근처 오더"에 평택 상차 오더와 "상차지 ○km". 김포·이천·대전 상차 오더는 50km 밖이라 빠진다. 오더 탭도 같다
3. **다른 앱에서 받은 배차 등록:** 홈 "내 배차"의 버튼 → 지금 여기·다녀온 곳·내비 즐겨찾기 중 고르기 → 등록되면 내 배차에 생긴다
4. **운행:** 배차 → 안내 시작 → 상차지 좌표로 geo fix + 가상 콘솔 기어 P → 3분 뒤 자동 도착
5. **대기 증빙:** 대기 화면 "대기 증빙 보내기" → QR의 주소(`/w/...`)를 컴퓨터 브라우저로 열어 대기 시간이 보이는지
6. **자동 떠남:** 반경 밖 좌표로 geo fix → 대기 화면에 "떠나고 있어요 · 00:30" → 30초 뒤 하차지 안내. 또는 가상 콘솔 속도 30km/h로 1분
7. **인수증:** 하차지 도착 → "인수증 받기" → QR 주소(`/r/...`)를 휴대폰이나 브라우저로 열어 서명 → 앱이 운행 완료로 바뀐다
8. **설정:** 이름 바꾸기, 차량 높이 ±, 기본 차량 바꾸기, 로그아웃

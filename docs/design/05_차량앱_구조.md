# 차량 앱 코드 구조

차량 앱(`android/app`)의 폴더 구조와 객체 사이의 역할을 정리한다. 서버 개발 관점에서 대응되는 개념을 같이 적었다. 2026-11-03 기준.

## 1. 한눈에 보기

요청 하나가 지나가는 길:

```
화면(Compose)  →  ViewModel  →  Repository(인터페이스)  →  Repository 구현  →  Retrofit API  →  서버
   그리기만         상태 관리       domain/                    data/              data/*/XxxApi
```

| 앱 | 하는 일 | 서버로 치면 |
|---|---|---|
| Compose 화면 (`ui/*Screen.kt`) | 상태를 받아 그리기만 한다. 버튼을 누르면 콜백을 부른다 | 뷰(HTML) |
| ViewModel (`ui/*ViewModel.kt`) | 화면 상태(`UiState`)를 들고, 사용자 동작을 받아 저장소를 부른다 | Controller + 화면용 상태 |
| Repository 인터페이스 (`domain/`) | "무엇을 할 수 있나"만 정한다 | Service 인터페이스 |
| Repository 구현 (`data/`) | 서버를 불러 결과를 앱 모델로 바꾼다 | ServiceImpl |
| Retrofit API (`data/*/XxxApi.kt`) | 서버 주소와 요청 모양 | 외부 API 클라이언트 (Feign) |
| DTO (`data/*/XxxDtos.kt`) | 서버 JSON과 같은 모양. `toDomain()`으로 앱 모델로 바꾼다 | Request/Response DTO |
| `di/AppContainer` | 객체를 만들고 서로 연결한다 | Spring의 Bean 설정 |

**규칙: 화살표 방향으로만 안다.** 화면은 ViewModel만 알고, ViewModel은 `domain/`의 인터페이스만 안다. 서버 통신(`data/`)은 바꿔 끼울 수 있다. 테스트에서 가짜 저장소(`FakeAuthRepository`)를 넣는 것도 이 덕분이다.

## 2. 폴더

```
com/ieo/app/
├── IeoApplication.kt        앱이 켜질 때 AppContainer를 만든다
├── MainActivity.kt          화면 이동 (시작 → 로그인 → 홈). 로그인 여부는 SessionManager를 따른다
│
├── di/                      객체 연결
│   ├── AppContainer.kt      앱 전체에 하나씩 있는 객체들 (세션, 저장소)
│   └── ViewModelFactories.kt
│
├── core/                    어느 기능에도 속하지 않는 공용 기반
│   ├── network/             서버 통신 공통
│   │   ├── ApiResult.kt     성공/실패를 값으로 (예외를 던지지 않는다)
│   │   ├── ApiError.kt      실패 종류: Server(서버 오류 응답) / Network(연결 실패) / Unexpected
│   │   ├── ApiCaller.kt     Retrofit 호출 → ApiResult. try/catch는 여기 한 곳에만
│   │   ├── NetworkClients.kt  Retrofit 두 개: public(로그인 전), authenticated(토큰 붙임)
│   │   ├── BearerTokenInterceptor.kt   Authorization 헤더 붙이기
│   │   └── TokenRefreshAuthenticator.kt 401이면 토큰 갱신 후 한 번 더
│   └── session/             로그인 상태와 토큰 보관
│       ├── SessionManager.kt   로그인 여부의 단일 출처 (isLoggedIn)
│       ├── TokenStore.kt       보관 인터페이스
│       ├── EncryptedTokenStore.kt + TokenCipher.kt  Android Keystore로 암호화해 저장
│       ├── TokenRefresher.kt   갱신 인터페이스 (구현은 data/auth)
│       └── DeviceInfo.kt       설치마다 만드는 deviceId
│
├── domain/                  앱이 다루는 개념 (서버·화면과 무관)
│   ├── auth/                AuthRepository, PhoneVerification, CarLoginSession …
│   ├── trip/                TripRepository, Trip, TripStop, TripStatus, StopType
│   ├── wait/                WaitRepository, WaitRecord, WaitPolicy(대기비 계산)
│   ├── ledger/              LedgerRepository, LedgerEntry, Receivables(가장 밀린 주선사), MonthlyLedger(월 요약·날짜별 묶기)
│   ├── expense/             ExpenseRepository, Expense, ExpenseCategory
│   ├── order/               OrderRepository, Order, DispatchRequest, ReportType
│   └── navi/                Navigator 인터페이스 (차량 내비)
│
├── data/                    domain 인터페이스의 구현 (서버 통신)
│   ├── auth/                AuthApi, AuthDtos, DefaultAuthRepository, ServerTokenRefresher
│   ├── trip/                TripApi, TripDtos, DefaultTripRepository
│   ├── wait/                WaitApi, WaitDtos, DefaultWaitRepository
│   ├── ledger/              LedgerApi, LedgerDtos, DefaultLedgerRepository
│   ├── order/               OrderApi, OrderDtos, DefaultOrderRepository
│   ├── expense/             ExpenseApi, ExpenseDtos, DefaultExpenseRepository
│   └── navi/                NaviGuide: Navigator를 Pleos NaviHelper로 구현
│
└── ui/                      화면. 기능별 폴더
    ├── theme/  common/      색, 금액 표기, DayTimeFormatter("오늘 15:00" 한국 시간 표기)
    ├── component/           공통 조각: WhiteSection·SectionTitle·ListRow·TagLine·FilterChip(IeoSection), IeoBottomSheet, 버튼, 키워드 태그
    ├── splash/
    ├── login/               LoginRoute(연결) · LoginScreen(그리기) · PhoneLoginViewModel · QrLoginViewModel
    ├── home/                HomeScreen · HomeViewModel(운행 진행) · HomeStateFactory(어느 화면인지) · AssignedTripMapper·OrderCardMapper(서버 값 → 카드)
    ├── orders/              OrdersRoute · OrdersScreen · OrdersViewModel · OrderUiMapper
    ├── ledger/              LedgerRoute · LedgerScreen · LedgerForms(경비·운행 추가, 운임 고치기) · LedgerViewModel · LedgerUiMapper
    └── main/                왼쪽 메뉴 + 본문
```

## 3. 새 기능을 붙이는 순서 (예: 설정)

1. `domain/account/`: 모델과 `AccountRepository` 인터페이스
2. `data/account/`: Retrofit API, DTO(`toDomain()`), `DefaultAccountRepository`
3. `di/AppContainer`: 저장소 한 줄 추가
4. `ui/settings/`: `SettingsUiState` + `SettingsViewModel`(+ `Factory`, `SettingsActions` 인터페이스) + `SettingsScreen`(상태만 받음) + `SettingsRoute`(둘을 잇는 곳)
5. 테스트: 가짜 저장소를 만들어 ViewModel을 시험 (예: `testing/FakeBooks`)

장부 탭(`ui/ledger/`)이 이 순서대로 만든 예시다.

## 4. 정해 둔 것

- **실패는 값으로:** 저장소는 예외 대신 `ApiResult`를 돌려준다. 화면은 `when`으로 성공과 실패를 모두 처리하고, 실패 문장은 `ApiError.message`를 그대로 보여 준다. 서버 오류 문장이 이미 한국어라서다.
- **로그인 이동은 세션이 정한다:** 로그인 성공, 로그아웃, 리프레시 토큰 만료 모두 `SessionManager.isLoggedIn`만 바뀌고, `MainActivity`가 그 값을 보고 화면을 바꾼다. ViewModel끼리 서로 부르지 않는다.
- **토큰 갱신:** 401이 오면 `TokenRefreshAuthenticator`가 한 번만 갱신한다. 서버가 리프레시 토큰을 거절하면 로그아웃하고, 서버에 닿지 못하면 로그인을 유지한다.
- **토큰 저장:** Android Keystore의 AES-GCM 키로 암호화해 저장한다. 키는 기기 밖으로 나가지 않는다.
- **서버 응답 변경에 강하게:** 모르는 필드는 무시하고(`ignoreUnknownKeys`), 모르는 enum이나 잘못된 날짜는 `mapResponse`가 `Unexpected`로 바꾼다. 앱이 죽지 않는다.
- **시간:** 서버 시각은 UTC(`Instant`)로 받고, 화면 표기는 한국 시각으로 바꾼다(`AssignedTripMapper`). 남은 시간 타이머는 기기 시계를 바꿔도 맞도록 `SystemClock.elapsedRealtime`을 쓴다.
- **의존성 주입 도구는 아직 쓰지 않는다:** `AppContainer`에서 손으로 연결한다. 객체가 많아지면 Hilt로 옮긴다.
- **모듈:** 지금은 Gradle 모듈 하나에 패키지로 나눴다. 패키지 경계가 위 규칙대로 지켜지고 있어서, 나중에 `:core`, `:data`, `:feature-login`처럼 Gradle 모듈로 쪼갤 때 폴더를 그대로 옮기면 된다.

## 5. 서버 주소

| 빌드 | 주소 | 설정 |
|---|---|---|
| 디버그 | `http://10.0.2.2:8080/` (에뮬레이터에서 본 내 컴퓨터) | `app/build.gradle.kts`의 `API_BASE_URL` |
| 배포 | `-PieoApiBaseUrl=https://.../` 로 넘긴다 | 정하지 않으면 동작하지 않는 주소 |

평문(http)은 디버그 빌드에서 `10.0.2.2`, `localhost`에만 허용한다 (`src/debug/res/xml/network_security_config.xml`).

## 6. 운행 진행 흐름

홈 화면은 서버의 운행 상태로 정해진다 (`HomeStateFactory`).

| 서버 운행 상태 | 홈 화면 | 다음으로 넘어가는 것 | 부르는 API |
|---|---|---|---|
| 진행 중인 운행 없음 | 운행 전: 내 배차 목록 | 배차를 눌러 "안내 시작" | `POST /api/trips/{id}/start` + 상차지 길 안내 |
| `TO_PICKUP` | 주행 중 (상차지로) | 내비가 "목적지 도착"을 알림 (안내가 꺼져 있으면 "도착했어요") | `POST .../stops/PICKUP/wait/arrive` |
| `AT_PICKUP` | 대기 중 → "상차 시작" → 상차 중 | "상차 시작", "상차 끝, 출발" | `.../wait/work-start`, `.../wait/depart` + 하차지 길 안내 |
| `IN_TRANSIT` | 주행 중 (하차지로) | 내비 도착 | `POST .../stops/DROPOFF/wait/arrive` |
| `AT_DROPOFF` | 대기 중 → 하차 중 | "하차 시작", "운행 완료" | `.../wait/work-start`, `.../wait/depart` (서버가 운행 완료·장부 기록) |

- 앱을 껐다 켜도 `GET /api/trips/current`와 `GET /api/trips/{id}/waits`로 하던 화면을 이어서 보여 준다.
- 대기 타이머와 대기비는 서버 시각(도착, 대기비 시작, 작업 시작)을 기기 시계로 바꿔 화면에서 센다. 대기비 계산(`WaitPolicy`)은 서버와 같은 규칙이다.
- **아직 손으로 하는 것:** 도착은 내비 도착 신호로 자동 처리하지만, 요구사항(WAIT-001)의 "반경 안 + 3분 정차" 판단은 아니다. 지오펜스와 기어·속도 신호는 에뮬레이터 확인 뒤에 붙인다.

## 7. 지금 서버와 연결된 것

| 화면 | 상태 |
|---|---|
| QR 로그인 | 연결됨: 서버 코드 → 2초마다 확인 → 승인되면 홈 |
| 휴대폰 로그인 | 연결됨. 가입된 차주 계정만 (차량에는 가입 화면이 없다) |
| 자동 로그인 | 저장된 토큰이 있으면 홈으로. 첫 요청에서 만료가 확인되면 로그인 화면으로 |
| 홈 "내 배차" | 연결됨: 끝나지 않은 운행을 상차 시각 순으로 |
| 운행 진행·대기 | 연결됨: 위 6장 |
| 홈 오늘 요약 | 연결됨: `GET /api/ledger/daily` (운행 수, 순수익) |
| 홈 미수금 경고 | 연결됨: `GET /api/ledger/receivables`에서 지급일이 지난 운임을 주선사별로 묶어 가장 오래 밀린 곳 하나 |
| 홈 오더 | 연결됨: `GET /api/orders` (내 차로 실을 수 있는 모집 중 오더 5건). 차량 위치가 없어 "모집 중인 오더"로 보여 주고, 실수익·주선사 지급 소요일은 비워 둔다 |
| 오더 탭 | 연결됨: 날짜 칩(전체·오늘·내일), 확정 기다리는 내 요청 띠(10분 타이머, 철회), 상세, 배차 요청, 신고. 주행 중에는 목록을 감춘다 |
| 장부 탭 | 연결됨: 장부(월 요약 + 날짜별, 월 이동) · 미수금 · 경비. 받음 표시, 대기비 받음, 운임 고치기, 경비 추가, 운행 직접 추가 |
| 상하차지 정보, 대기 증빙 보내기, 설정 탭 | 준비 중 |

홈의 샘플 데이터(`SampleHomeData`)는 이제 디버그 빌드의 "대기 샘플·주행 샘플"과 미리보기에만 쓴다.

# 주선사 기능 인계

주선사(07 주선사) 기능은 다른 개발자가 맡는다. 이 문서는 2026-11-03 기준으로 서버(`ieo-server`)에 이미 있는 것과 남은 일을 정리한다.

## 1. 지금 있는 것

### 엔티티

| 엔티티 | 위치 | 내용 |
|---|---|---|
| `Broker` | `domain/broker/entity` | 상호, 사업자등록번호(유니크), 운송주선사업 허가 번호, 대표자, 정산 주기(기본 30일) |
| `BrokerMember` | `domain/broker/entity` | 담당자. `users.id`를 PK로 쓰는 1:1 프로필. 소속 주선사, 직책(`OWNER` / `STAFF`) |
| `WaitPolicy` | `domain/wait/entity` | 주선사별 대기비 정책. 고치지 않고 새로 만들며, 켜진 정책은 주선사당 하나 |
| `Order` | `domain/dispatch/entity` | 주선사가 올린 오더. `broker`, `createdBy`(담당자) |

### 주선사 계정으로 쓰는 API (이미 동작)

담당자(`BrokerMember`)가 있는 계정만 쓸 수 있고, 다른 회사 데이터는 404로 숨긴다.

| API | 하는 일 | 권한 |
|---|---|---|
| `POST /api/broker/orders` | 오더 등록 | 담당자 |
| `GET /api/broker/orders?status&page&size` | 우리 회사 오더 목록 (페이지, 대기 중 요청 수) | 담당자 |
| `GET /api/broker/orders/{id}` | 오더 상세 | 담당자 |
| `GET /api/broker/orders/{id}/requests` | 요청한 차주 목록 (차량, 완료 운행 수, 늦은 취소 수) | 담당자 |
| `POST /api/broker/orders/{id}/requests/{requestId}/confirm` | 배차 확정 → 차주 운행 생성 | 담당자 |
| `POST /api/broker/orders/{id}/cancel` | 확정된 배차 취소 (다시 모집 또는 내리기) | 담당자 |
| `POST /api/broker/orders/{id}/close` | 오더 내리기 | 담당자 |
| `GET` / `PUT /api/brokers/me/wait-policy` | 대기비 정책 조회 / 바꾸기 | 조회는 담당자, 바꾸기는 대표(`OWNER`)만 |
| `GET /api/public/wait-proofs/{token}` | 차주가 보낸 대기 증빙 데이터 (로그인 없이). 사람이 보는 페이지는 `/w/{token}` | 누구나 |

## 2. 빠진 것 (우선순위 순)

### 2-1. 주선사 가입 — 가장 먼저 필요

**지금은 주선사 회사와 담당자를 만드는 API가 없다.** 가입 API(`POST /api/auth/signup`)에 `role: BROKER`를 보내면 `User`만 생기고 `Broker`·`BrokerMember`는 생기지 않는다. 그래서 실제로는 위 주선사 API를 쓸 수 없다(테스트에서만 엔티티를 직접 만든다).

할 일 (BRK-001):
- 가입할 때 사업자 정보(상호, 사업자등록번호, 운송주선사업 허가 번호)를 받아 `Broker`와 첫 담당자(`OWNER`)를 만든다.
- 이미 등록된 사업자등록번호면 새 회사를 만들지 않는다. 기존 회사에 합류하는 방법(초대)을 정해야 한다.
- 허가 번호가 없으면 오더를 올릴 수 없게 한다. 지금 `Broker.licenseNumber`는 필수 컬럼이다.

### 2-2. 담당자 관리
- 대표가 담당자를 휴대폰 번호로 초대, 직책 변경, 내보내기 (BRK-001 "담당자 여러 명")
- 플랜별 담당자 수 제한은 12 요금제를 만든 뒤

### 2-3. 정산 주기 설정 (BRK-003)
- `Broker.changeSettlementDays()`는 있지만 API가 없다.
- 장부의 지급 예정일이 이 값을 쓴다: 오더의 `expectedPaymentDays` → 주선사 `settlementDays` → 30일 순서 (`LedgerRecorder.settlementDays`).

### 2-4. 단골 차주 연결 — `BrokerDriverLink` (BRK-002, 011)
- 엔티티 없음. 요구사항 필드: brokerId, driverId, status(INVITED/LINKED/REVOKED), linkedAt
- 주선사가 차주를 휴대폰 번호로 초대하고 차주가 수락하면 연결
- 연결된 차주의 위치만 볼 수 있다. 위치 공유 개인정보 동의 문구가 미결이다.
- 차주가 내 정보에서 주선사 공유 동의를 끄면(ACC-006, 2026-11-10) `BrokerTripResponse`의 `locationVisible`이 false가 되고 `location`·`etaAt`·`progressPercent`가 비고, 도착 시각 문자도 가지 않는다. 콘솔은 이 값들이 비어 있어도 화면이 깨지지 않아야 한다. 단골 수락은 공유 동의로 기록된다.
- 지정 배차는 이미 있다: `Order.targetDriver`. 지금은 아무 차주나 지정할 수 있으니, 연결이 생기면 **연결된 차주만 지정**하도록 `BrokerOrderService.register`를 고친다.

### 2-5. 진행 중 운행 확인 (BRK-020, 021, 022)
- 주선사용 운행 목록·상세 API가 없다. `Trip.broker`로 거르면 된다.
- 현재 위치와 ETA는 운행 위치 기록(`LocationPoint`)과 ETA 알림(`EtaNotice`)이 없어서 아직 못 보여 준다 (01 운행 담당과 맞춰야 함).
- 대기 증빙은 운행의 대기 기록(`WaitRecord`)과 증빙(`WaitProof`)으로 볼 수 있다.
- 전자인수증은 서버 API가 있다(`domain/delivery`, `DeliveryProof`). 주선사가 보려면 운행의 인수증 링크를 콘솔에 보여 주면 된다. 수하인 서명 페이지는 `/r/{token}`(서버 `static/receipt.html`), 데이터는 `/api/public/delivery-proofs/{token}`. 주선사에게 자동 전달(POD-007)은 09 알림 뒤.

### 2-5-1. 오더 화물 종류를 enum으로
- 지금 `Order.cargoType`은 자유 입력이라 배차 추천에서 "냉동·이사 제외" 같은 조건으로 거를 수 없다.
- 콘솔 오더 등록 화면을 만들 때 화물 종류 enum(일반, 냉동·냉장, 이사, 위험물 등)을 추가해 고르게 하고, 자세한 내용은 지금의 자유 입력에 남긴다. 배경: [04_배차추천.md](04_배차추천.md)

### 2-6. 신뢰 지표 — `BrokerMetrics` (BRK-030~032, P3)
- 엔티티 없음. 평균 지급 소요일, 지급 지연 비율, 대기비 지급 비율, 평균 대기 시간
- 재료는 이미 있다: 장부(`LedgerEntry.expectedPaymentDate`, `paidAt`), 대기비(`ExtraIncome.paidAt`), 대기 기록
- 상하차지 통계(`SiteStats`)처럼 캐시 테이블로 두고, 원본(장부·대기 기록)이 바뀔 때 처음부터 다시 계산하는 방식을 권한다.
- 완료 운행 20건 이상일 때만 공개

### 2-7. 정회원 리포트 (BRK-040~045, P3)
- 노선별 운임, 상하차지 대기, 회사 리포트. 2차 PT에서는 샘플 데이터로 시연

## 3. 웹 콘솔(React)을 붙일 때 서버에서 챙길 것

- **CORS 설정이 없다.** 콘솔이 다른 주소(예: `localhost:5173`)에서 API를 부르면 브라우저가 막는다. 허용 주소를 설정 파일로 받게 `WebConfig`에 추가한다.
- **로그인:** 지금은 휴대폰 인증 → JWT(액세스 30분, 리프레시 30일) 하나뿐이다. 콘솔도 같은 방식을 쓰면 추가 작업이 없다. 이메일·비밀번호 로그인이 필요한지 정해야 한다. 설계: [01_로그인.md](01_로그인.md)
- **동시 수정:** `Order`에는 `@Version`이 있어서 담당자 둘이 동시에 확정하면 늦은 쪽이 409 `ORDER_409_CONFLICT`를 받는다. 콘솔은 이때 "새로 고침"을 안내하면 된다.
- 응답에는 enum과 함께 화면 표기(`tonnageLabel`, `bodyTypeLabel` 등)를 내려준다. 콘솔이 직접 번역하지 않아도 된다.

## 4. 서버 코드 규칙 (지금까지 지킨 것)

- 도메인별 패키지: `domain/{도메인}/{entity, enums, repository, service, dto, controller}`
- 엔티티는 정적 팩토리(`create`, `of`)로 만들고, 값 검사와 상태 전환은 엔티티 메서드가 한다. 실패는 `BusinessException(ErrorCode)`
- 오류 코드는 `global/error/ErrorCode`에 도메인별로 모은다 (예: `ORDER_404`, `WAIT_403_POLICY`)
- **다른 데이터로 계산할 수 있는 값은 컬럼으로 만들지 않는다.** 예외: 장부처럼 "그때의 기록"이어야 하는 값, 상하차지 통계처럼 자주 읽는 캐시
- 남의 데이터는 403이 아니라 404로 숨긴다
- 시각은 `Instant`(UTC)로 저장하고, 날짜가 필요하면 `KoreanDate`로 한국 날짜로 바꾼다
- 시간 로직은 주입받은 `Clock`을 쓴다
- 스케줄러(`@Scheduled`)는 지금 모두 꺼 두었다 (`AuthRecordCleaner`, `SiteStatsCalculator`)
- 테스트: `@SpringBootTest` + `@ActiveProfiles("test")` + `@Transactional` + MockMvc, H2 메모리 DB
- 커밋 메시지는 한국어, 관련 요구사항 ID를 붙인다
